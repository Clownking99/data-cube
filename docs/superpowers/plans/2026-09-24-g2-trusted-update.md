# G2 / M2 可信更新与失败恢复

基线：main `8a729746a7f93c9399963930836ac69e4721eec8`，tracked 工作区干净。独立 `codex/datacube-g2-trusted-update` worktree。用户“继续推进”承接 G2；不自动开展 M3–M8，不创建额外目标/预算。

## 当前缺口与边界

UpdateApplier 只检查 Content-Length；固定临时文件、staging、脚本和 .bak；跨 cmd/PowerShell 拼接路径；新进程启动前即删除备份。ReleaseInfo/Checker 未承载可信发布元数据，UpdateService 关闭只抑制回调而不取消在途下载。以上为本轮源码事实；未连接发布服务器、未执行真实更新。

## 威胁与实施决定

| 威胁 | 决定 / 可测行为 |
| --- | --- |
| 传输损坏、替换资产、错误版本/平台 | 签名清单固定 tag/version/windows-x64/精确资产名/大小/SHA-256；下载流限额，完整校验后才可交接 |
| Release 被替换 | Ed25519 验证精确 UTF-8 清单字节；信任公钥来自随程序审查分发的资源，不信任同一 Release 提供的新公钥 |
| 尚无受信任公钥或签名 | 自动执行默认关闭，保留官方手动下载页；无降级到仅长度/未认证 hash 的旁路；测试仅生成内存临时密钥 |
| 下载阻塞、取消、关闭、并发请求 | 受限时间和大小、关闭流/中断，单次活动请求；取消先于交接时零进程启动；交接后不误称取消已回滚 |
| 临时名抢占与目录误判 | 唯一工作目录，精确 appDir 和同卷 staging；拒绝符号链接/重解析路径、不按同名应用猜目标 |
| 恶意压缩包 | 拒绝越界、绝对路径、Windows 别名/设备名、重复文件、过量条目/解压总量；要求完整 DataCube 结构 |
| 替换中断与重启失败 | 单一 PowerShell helper 使用 LiteralPath，不跨 shell 拼接；状态文件区分准备/替换/启动/确认；保留旧版及失败现场；新版本确认启动前不删除备份 |
| 本地同权限攻击者 | 客户端签名不是操作系统权限沙箱；拥有修改安装目录/程序/受信任资源权限的攻击者不在真实性保证内，仍检查路径/哈希以减少竞态与误操作 |

## 实施与验证顺序

1. 重新运行 updater 现有定向测试与 buildSrc，记录实际证据。
2. 严格发布清单、受信任公钥和下载校验；直接 API 不接受未验证 Path 来启动更新。
3. 独占暂存、压缩包校验和注入进程边界；真实 helper 仅在合成临时安装树内验证，进程启动通过测试替身。
4. 服务取消/关闭/单次交接与 UI 文案、启动确认。保存现有应用关闭与事务守卫。
5. 定向异常矩阵、全量、fresh buildSrc、jpackageImage、差异审查；本地提交合并 main 并复验。

只使用 mock、合成 profile、临时目录；不读取 .testagent/、真实连接/凭据/历史/业务文件，不下载安装更新，不推送/tag/PR/发布，不配置远端签名。沿用测试技能的行为断言原则；按项目约定不添加通用流水线、多代理或 .testagent 状态文件。

## 外部依赖

发布公钥选择、受保护的签名流水线、证书/凭据/轮换实施及真实安装升级/恢复需后续明确授权。合成 profile 的原生桌面更新交互仍未人工验证。本次本地工作完成后，M2 仍列为部分完成/待外部验收，不宣传“安全更新已全面验证”。
