# G3 / M3 页面修改与显式保存

基线：main `9b334a18b0d5561ba86e13b1128dae419c0ead24`，tracked 干净。用户继续推进承接 G3；独立 `codex/datacube-g3-explicit-save` worktree。本轮不扩大到 M4–M8；M2 生产签名/真实升级待验不变。

## 实施前决定

1. 页面级内存变更集：新增、修改、待删除；离行、Enter、翻页不触发写入。新增后删除直接移除，逐项/全部放弃恢复未保存状态。仅“保存到数据库”执行本页变更；“预览修改 SQL”只展示，不保存文件或写日志。
2. 首版采用**逐行独立事务，按原始加载/新增顺序执行，首个失败停止**。列排序只改变展示顺序，不改变预览与保存的固定顺序。每行专用连接，沿用 M1 目标/生产确认/配置版本门禁，不与 SQL 编辑器或其他标签事务混用。成功行已提交，后续失败不能整体撤销；用户确认前和结果中明确说明。
3. 本次保存冻结目标、表、行身份、旧值和新值，一次确认只能使用一次。每行开始前复查配置和取消；设置变化不重放已提交行。取消仅停止尚未执行行，不声称回滚已提交部分。
4. 保留且扩展影响行数护栏至 INSERT。UPDATE/DELETE 用主键及可比较旧值检测冲突（无主键沿用可匹配旧值）；0 行/多行分别说明，回滚失败或提交应答不确定单列 UNKNOWN，禁止盲目重试该行。LOB/二进制等不能可靠比较的值不伪称已覆盖。
5. 失败后保留未提交修改及逐行结果；成功行锁定为已保存待刷新，避免使用错误旧值再次提交。全部成功后明确提供刷新；刷新失败不把已提交行重新标为未保存。UNKNOWN 行保持锁定，用户核对数据库后显式放弃本地标记/刷新。
6. 翻页、刷新、执行过滤及关闭遇到未保存修改时默认取消；只提供“放弃未保存修改并继续”或取消，保存必须使用显式保存入口。保存期间交互关闭被拒绝，页面保留结果；强制资源清理只停止后续行并释放任务，不承诺撤回在途写入。
7. SQL 预览与 JDBC 执行共用参数化 SQL 构造，参数标识旧值/新值、NULL、空串及列含义；预览长度有边界并标明省略，原值不自动日志化。Oracle 空字符串遵循数据库 NULL 语义，不能跨库保证相同。
8. 审查确认 AppShell 已全局处理 SQL 文件的 `Ctrl+S`；数据库写入只提供“保存到数据库”按钮，不复用文件保存快捷键或修改全局绑定。

- M3a：基线复验；变更集、撤销与焦点/选中行为，消除隐式写入。
- M3b：不可变保存请求、共享 SQL 预览、逐行结果与事务异常分类；M1 只读/生产确认回归。
- M3c：翻页/刷新/过滤/关闭/退出守卫；保存期间取消剩余、迟到回调及多标签隔离。
