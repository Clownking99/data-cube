## 基线与事实

- main：`b6622c95d5efc0b240dc7ae4b788f44542c87b5a`，范围内干净。G9 最终 Verify 37828177473 四任务通过，跟进已 PAUSED；这些是历史基线，不是 G10 测试证据。
- `RespCodec` 按声明长度创建 ArrayList/readNBytes，readLine 无上限、数组递归无深度/总节点预算。旧合成 13 字节数组头曾在独占 32 MiB JVM 中触发 OOM；G10 必须记录当前源码的新诊断。
- `RespClient` 把所有 IOException 当传输断开，对 allowlist 读命令重试。资源拒绝/协议损坏不能反复执行；部分响应不能留给下一命令。AUTH/SELECT 也经过相同解码入口。
- `RedisConsoleSupport.format` 会递归展开、十六进制放大；控制台保留无上限的 Label 和历史。键浏览器累计 loadedKeys，并递归建树；JSON 缩进可能将短的深嵌套输入大幅放大。
- 浏览器已有 1 MiB 字符串预览、4096 字节 GETRANGE 和 collection 页大小，不重复实现。SCAN COUNT 只是工作量提示，不能作为返回条目上限；单页可能多于 COUNT。参见 [Redis SCAN](https://redis.io/docs/latest/commands/scan/)；长度和类型语义按 [RESP 规范](https://redis.io/docs/latest/develop/reference/protocol-spec/)。两页于本轮核对。

## 范围与边界

只处理 RESP2 请求/响应的本地资源准入、失败连接处置、Redis 显示/保留量及其必要生命周期回归。保留五类编辑、二进制值、AUTH/SELECT、普通 server error、现有读重试 allowlist 和写结果不确定语义。

不新增 RESP3/Cluster/TLS、连接池、导入导出、权限模型或数据库类型；不重写全局 FX runner/AppShell，不恢复 SQL 美化主线。不改变服务器配置或读取真实 Redis。

`.testagent` 禁读禁改禁枚举，所有 Git 状态/搜索/暂存明确排除。不得读取原有 profile、连接、凭据、历史或业务文件。只用内存流、mock、合成 profile、独占 UUID 目录和显式绑定 127.0.0.1 的临时脚本服务器；不运行真实 Redis/pg_dump，不接触已有 Oracle 表。开发不 merge main/push/fetch/tag/PR/发布/安装更新/外部联系；root 仅沿用 main 推送及精确 SHA CI 授权，必要时单命令 7897 代理。v3.2.9、旧 datacube 和 datacube-g9 PAUSED 状态不改。

## 分阶段契约

### P0：冻结预算与失败分类

开发先提交文件/调用矩阵、预算含义、普通异常与资源/协议异常区分、连接所有权和测试方案，由 root 审查再准入 P1。常规数值调整记录理由即可，不要求维护者每步确认。

以下为设计起点，不是 Redis 协议最大值，也不宣称 JVM RSS 硬上限。最终值须集中定义、不可被任意环境开关绕过，测试可注入更小的不可变预算：

| 资源 | 候选预算 | 验收语义 |
| --- | --- | --- |
| 单 bulk / 单行 | 8 MiB / 64 KiB | 大分配或无限累积前拒绝；数字头可另设更小上限 |
| 单响应总 wire bytes / 总节点 | 16 MiB / 100,000 | 所有嵌套共享，不按子数组重置，溢出安全 |
| 单数组元素 / 深度 | 10,000 / 32 | 巨大头即拒绝，不按不可信长度先分配 |
| 单请求编码 | 8 MiB payload、16 MiB frame、10,000 参数 | 预检后再复制/写出；拒绝时零发送，不泄露命令或凭据 |
| 响应读取总期限 | 30 秒候选 | 单调时间，不能每个 read/子响应重新计时；不声称覆盖未实现的 DNS/阻塞写等阶段 |
| 控制台单条显示 / 保留 | 64 Ki UTF-16 / 200 条且总 512 Ki UTF-16 | 截断明确标注，仅显示预览；历史独立限制 100 条且总 64 Ki UTF-16 |
| 累计键 / 键字节 / 树节点与深度 | 5,000 / 2 MiB / 20,000、32 | 多个维度都检查；不能只限制键数却放任长键分隔后爆炸 |
| 集合页面 / 单元格/总显示 | 1,000 行 / 4 Ki、256 Ki UTF-16 | COUNT 外另做实际检查；原始值与显示预览身份分离 |

### P1a：协议解码、编码与连接恢复

- 超长头、bulk、array、累积小对象、过深嵌套、整数溢出和错误 CRLF 在受控异常下停止，不依赖捕获 OOM/StackOverflow 作产品保护。null/empty/二进制/边界恰好值保持兼容。
- 同一响应的字节、节点、深度预算覆盖 simple/error/integer/bulk/array；声明长度、wire 计数和分配前检查的对应关系写清楚。避免通过中间副本绕开合理峰值上限。
- 资源超限、已知格式损坏和读取期限耗尽立即废弃本次 socket，不排空任意大尾部，不自动重放。下一次显式调用可在新连接恢复 AUTH/SELECT；普通完整顶层 server error 保持可用连接。嵌套 error 若提前抛出且响应未读完，必须避免残留响应串线。
- 写命令如果已经发送，错误说明保留“结果可能已生效/不重放”；发送前拒绝明确为未发送。客户端新建的预算/协议/期限拒绝与审计日志不得带命令、key/value、认证信息或被拒绝的原始字节。正常完整顶层 server error 的既有消息在行长/总预算内保留，不新增全局错误脱敏改造或普遍放宽原精确消息测试。
- 传输断开后的现有安全读重试仍单独证明；预算/协议拒绝不偷用该重试。关闭和并发调用不误关后继连接，所有新线程/计时器/loopback socket 要有物理结算。读取期限和 close 的真实范围必须写实，不把逻辑失败等同即时物理停止。
- 重连恢复已确认的当前 DB：typed/raw SELECT 明确成功后更新恢复身份；失败或已发送但结果不确定时不把未确认目标当成功，也不自动重放 SELECT。root 的新 loopback 诊断已确认现有 SELECT 7 成功后会错误恢复初始 DB 2。复杂 raw 会话状态若无法可靠恢复，必须显式失效，不静默向错误 DB 继续操作；不为此新增完整 CLI 状态机。

### P1b：有界展示与保留

- 控制台格式化预算在构造大 String/hex/缩进之前生效；避免深递归和未知对象任意 toString。响应预览明确显示省略，不把截断值当完整结果；输出和历史按条数与总字符双重收敛，输入在 tokenize/编码之前准入。
- 键树按实际 key/字节/节点/层级检查，先构造可接受的候选再提交 UI 状态。超限保留已显示结果、明确“未完整加载/请缩小 MATCH”，不能提前推进 cursor 丢掉未展示页，不能假报扫描完成。刷新/切库/关闭/迟到回调恢复原有有效生命周期。
- collection 实际页面超过预算时明确拒绝/要求缩小，不能悄悄丢元素后推进 cursor。文本/hex/JSON 都限制放大；不截断可保存编辑值，显示预览必须禁用对预览的保存，保留完整 raw 身份的既有行操作不误用展示字符串。
- 原有字符串预览保留；“加载完整值”不能绕过硬预算。STRLEN 与 GET 之间发生增长时仍由底层限制兜底，不把 STRLEN 当安全证明。

## 必须覆盖的证据

1. 小堆独占子 JVM 的巨大声明、长行、深数组；边界等于/加一、聚合多项各自合法但整体超限、计数溢出。只读取预算允许的输入，失败发生于危险分配前。
2. AUTH/SELECT/业务响应分别超限；拒绝后 peer EOF、客户端抛出、零重试、下一次新连接认证恢复；普通服务端错误可继续；嵌套错误尾部不污染下一调用。
3. 连续慢片段、提前 EOF、畸形终止符、正常二进制值；读取期限不被持续流量重置。受控时钟/同步优先，少量真实 loopback 证明物理关闭，不靠长 sleep 或加 timeout 取绿。
4. 请求恰好/超过限额时是否发送；非幂等写发送后拒绝/断开不重放；已有安全读重试仍正确。
5. 多次 SCAN 总量、COUNT 外返回、重复键、巨长多分隔键、失败后 cursor/旧树、刷新/切库；控制台历史/输出淘汰、深/二进制格式化、预览禁保存、迟到回调与关闭。
6. 首次失败及后来修正都保留。新证据不使用旧 XML/UP-TO-DATE 替代；报告应用预算及余留真实网络/OS/桌面局限。
7. 格式化/候选页预算拒绝不能逃逸 FX success callback 导致 input/busy 卡住；已确认 SELECT 后重连保持 DB，未确认 SELECT 不重放，复杂状态不可恢复时明确失效。
