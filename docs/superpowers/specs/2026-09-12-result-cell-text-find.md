# 单元格只读正文查找

基线 main `4714114`，独立 `codex/result-cell-find`。上一轮解决行详情字段定位，本轮解决打开长单元格后定位正文片段的问题；这是合成使用场景推导，不是用户调研结论。[DBeaver Value Panel](https://dbeaver.com/docs/team-edition/desktop/Value-Panel/) 提供长文本阅读的产品参照，本轮不实现其编辑或格式化能力。

## 范围与交互

- 仅“查看单元格”增加常驻查找框、上一个/下一个、区分大小写和计数；不增加主工具栏入口，也不改变行详情。
- 对 TextArea 实际显示的只读文本做字面、不重叠匹配，默认忽略大小写；保留空格，不执行正则、SQL 或标记。使用显示文本的 UTF-16 偏移，避免 CR/LF 规范化造成错位。
- 沿用快照 65,536 UTF-16 单元上限，查找词最多 1,024 单元，最多定位前 10,000 处。超长词整体拒绝；超过匹配上限明确要求缩小查找范围，不暗示搜索了未显示的尾部或完整数据库原值。
- 输入或切换大小写只更新计数，不自动改变正文选区。显式导航从当前选区之后/之前查找，首尾循环；无匹配时禁用导航并保持正文选择。清空恢复输入提示。
- Ctrl+F 聚焦并全选查找词，输入框 Enter/Shift+Enter 和窗口 F3/Shift+F3 导航；Esc 保留一次关闭。支持自动换行、明暗主题和 480/720 窗宽，长警告可换行。
- 焦点留在查找框时，正文选中的匹配仍使用有对比度的品牌实色底与白字；样式只作用于单元格正文，不改变其他文本区。输入框空提示在明暗主题及聚焦时可读。
- helper 仅持有本地 UI 和结果列表，关闭后解除监听、禁用旧操作。不连接数据库、不复制剪贴板、不读取/保存文件或历史，不改变原结果、SQL 文档或撤销栈。
