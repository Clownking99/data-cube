# SQL 美化输出预算

## 本轮范围

继续完善复杂 SQL 美化的稳定性。现有编辑器单次输入范围限制为 256 Ki UTF-16 单元，完整文本与替换后结果限制为 8 Mi；但结果检查发生在排版完成之后。深层 CASE、子查询及长表达式对齐可能让较小输入生成大量空格，先占用内存再被拒绝。

只修改 SqlFormatter 的输出构建，不改执行、连接、保存或 UI 操作，不添加依赖和后台任务。

## 行为

- 排版工作缓冲区最多 8 Mi UTF-16 单元，与既有结果上限保持一致。每次追加 token、标点、换行或缩进前检查剩余空间。
- 整段缩进先检查，再生成；不能先分配一个可能超限的空格字符串。
- 多语句共用同一预算，分号不重置预算。
- 超限抛出不含 SQL 原文的 IllegalArgumentException，不返回半截结果。既有编辑器错误处理保留文本、选区和撤销历史，提示缩小范围。
- 未超限保持现有排版；每次调用独立，拒绝一次不影响下一次美化。
- 预算按 Java String 的 UTF-16 单元计数，不按 Unicode 码点、字符显示宽度或文件字节数计数。

这是生成工作缓冲区上限，包含最终 strip 之前的临时尾部空白，可能比仅检查最终结果更保守。不是 JVM 总内存上限、执行时间上限或完整方言语法保障；输入分词仍由既有编辑器范围限制约束。词法不完整时保留原文的路径不进入生成器。

## 验证

先增加纯函数反例：小输入的深层 CASE / 子查询输出膨胀、跨语句累计，以及含补充平面字符的 8 Mi 前一单元/恰好/后一单元边界。验证正常结果、拒绝后的恢复与既有编辑器失败保护。

依次跑 SqlFormatterTest、格式化相关定向回归、clean test 和 jpackageImage。记录本地结果，不宣称真实数据库、原生窗口或远端 CI 验收；本轮仅本地提交、合并回 main，不推送或发布。
