# 执行概览恢复执行顺序

基线 main `8e0fc8a`。概览已支持按耗时及其他列排序，但回看原始执行过程仍需要手动处理表头排序。增加“恢复执行顺序”，仅对当前保留的执行概览生效，不重新执行 SQL。

- 按概览捕获时的记录顺序恢复，不按可能重复或非递增的语句编号重排；清除所有排序列。
- 保留 SQL 摘要关键词、仅看异常、超限拒绝提示与原始计数分母，只在这些条件下恢复次序。零匹配时也可清除排序，之后放宽筛选仍按原始顺序展示。
- 保留仍可见的所选记录身份；无选择不代选。沿用既有筛选的单条选择规则；关闭已打开的旧详情，需要时重新查看。后续“查看结果”仍对应原始记录。
- 没有活动排序且可见行已按原顺序时禁用且动作无副作用；手动取消表头排序但行仍乱序时仍可恢复。执行中、关闭、禁用、离开概览后拒绝迟到动作。新批次不恢复旧行。沿用前 1,000 条保留上限，不扩大结果集。
- 不改 SQL、文件、撤销记录、批次总汇、结果下拉框或导出范围；不修改查询结果表的排序，不改列布局。
- 入口使用现有 FlowPane 自然换行，保留正常表头交互和原生 Tab/Space；不新增全局快捷键或持久设置。

生产范围仅 `SqlScriptDetails`。复用现有离线面板测试 fixture，先验证缺失入口，再实现和复跑概览相关回归、全量测试及开发打包。通过隔离合成桌面验收原生表头排序、鼠标/键盘恢复、筛选与明暗宽窄布局，完成后快进本地 main。本轮不推送、不打 tag、不访问真实连接/SQL/剪贴板或 `.testagent/`。
