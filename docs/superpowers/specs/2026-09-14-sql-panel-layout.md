# SQL 编辑区与结果区布局

## 问题与范围

SQL 标签目前固定上下分屏。编写离线文件时空结果区占用空间，检查宽长结果时也只能拖动分隔条。
参考 DBeaver 官方 SQL Editor 的面板布局能力，本轮提供当前标签内的三种显示模式：上下分屏、仅看 SQL、仅看结果。
参考：https://dbeaver.com/docs/dbeaver/SQL-Editor/

## 交互与安全边界

- 主工具栏保留一个始终可达的“布局”菜单，标示当前模式；默认上下分屏。
- 使用同一编辑器与结果容器；保留 SQL、选区、撤销、文件脏状态、结果列和选择。
- 离开分屏时记住分隔位置；连续切换单区模式不覆盖它；返回分屏时恢复。
- 隐藏编辑器前关闭补全、查找/替换和跳转行浮层，取消尚未执行的替换意图。
- 仅看结果时，显式使用查找、替换或跳转行会先回到分屏。
- 查询完成可以更新隐藏结果，但不主动切换布局；布局本身不执行 SQL、不访问数据库、不保存文件。
- 关闭、任务域关闭、文件操作忙碌、草稿冻结和禁用状态下拒绝迟到的布局动作。
- 不持久化，不增加快捷键，不增加水平分屏、拖拽停靠或多结果集能力。

3. 定向测试证明节点、分隔位置、编辑与结果状态、操作边界及窄宽/主题布局。
4. 全量测试和打包；隔离配置的桌面样例使用合成 SQL/结果验证真实交互，不读取用户连接。
