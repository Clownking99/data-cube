# SQL 美化注释与常见子句安全增强

状态：已实现，等待本地整合。

## 用户问题

复杂 SQL 的词法美化不能只关注缩进。行注释 `-- ...` 如果被压缩到下一条 SQL 的同一行，会吞掉后续语句并改变执行语义；同时分页、聚合过滤和 DDL 列表等常见结构需要更完整的关键字与间距支持。

## 本轮行为

- 行注释作为行边界处理：注释保留在当前逻辑行末，后续 SQL 强制从下一行开始，避免 `--` 吞掉语句。
- 增补 `FETCH FIRST/NEXT ... ONLY`、`NULLS LAST/FIRST`、`FILTER (WHERE ...)` 以及递归 CTE、Oracle 层级查询常见关键字的大小写识别。
- DDL 对象声明后的列/参数列表使用 `CREATE TABLE t (`、`CREATE INDEX i (` 等可读间距；函数调用仍保持 `COUNT(`、`VARCHAR2(` 等紧凑形式。
- 仅修正词法排版与空白，不执行 SQL、不连接数据库、不引入第三方 parser。

## 明确不做

- 不尝试根据原始换行推断注释应否独占一行；输入已被压缩时只保证语义安全的行终止。
- 不把关键字集合扩展为完整 Oracle/PostgreSQL 方言语法，也不验证 SQL 是否可执行。
