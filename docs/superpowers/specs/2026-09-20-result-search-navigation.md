# 查询结果搜索键盘连续性

基线 main `026c6e4`。结果工具栏已有只搜索当前已加载数据的搜索框，但根级查找处理总是打开 SQL 查找；上一轮原生暗色截图中搜索提示也不明显。本轮只优化已有搜索入口，不增加新筛选算法或数据库请求。

- 当前显示查询结果，按键源在结果表或结果工具栏内时，既有“查找”快捷键（默认 Ctrl+F）聚焦搜索框并全选已有搜索词。不带入单元格值，不改变筛选、选区、排序、SQL 或面板布局。
- SQL 编辑区及非查询结果仍走既有 SQL 查找。工具栏“查找”按钮仍明确查找 SQL。快捷键设置保持 `sql.find` 键和默认组合，说明改为 SQL 文本/当前查询结果；用户改绑即时生效。
- 仅搜索框内的无修饰键 Esc 提交待处理的本地搜索文字并返回结果表，保留筛选词、列条件，不清空筛选，不自动选中第一行。Ctrl/Alt/Shift/Meta+Esc 不拦截。
- 零匹配和空查询可继续聚焦搜索，以便更改条件；忙碌、关闭、队列停止、禁用控件时拒绝本次快捷键转移焦点或提交搜索，既有防抖行为不变。弹窗菜单沿用自身键盘处理，不改变全局快捷键分发。
- 搜索提示使用已有主题语义色，明暗、聚焦前后均可辨认；提示明确搜索仅限已加载结果，Esc 返回且保留条件。

步骤：明确回归范围并接入现有根事件过滤器与工具栏 → 定向/全量测试和开发镜像 → 隔离合成桌面键盘验证 → 本地 main 合并及复验。若桌面不可用，记录待验项并停止原生操作，不用自动测试冒充原生结果。真实连接、SQL 文件、历史、凭据和剪贴板不在验收范围；不推送、不打 tag。
