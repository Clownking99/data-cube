# SQL 草稿恢复设计

## 授权、目标与交付范围

用户已授权参考主流数据库工具自主推进常规产品设计，不再逐项确认；使用独立 worktree，完成增量后本地合并 main。本轮不推送、不打 tag、不安装、不访问真实数据库、凭据或 SQL 历史，`.testagent/` 原样保留且不读取。

P1 目标是保护未执行和未主动保存的 SQL，显示真实保存状态，并能在重启后取回精确文本。P2 才恢复标签顺序/当前标签/光标；P3 才引入用户管理的 `.sql` 文件。存储基础通过不等于用户可用恢复已经交付。

## 依据与方案选择

2026-08-30 核对官方资料：[DataGrip query consoles](https://www.jetbrains.com/help/datagrip/query-consoles.html) 将控制台文本作为关联数据源的文件存储；[DBeaver script management](https://dbeaver.com/docs/dbeaver/Script-Management/) 区分控制台、保存脚本和再次打开脚本。这些支持“文本可持续保留”的产品方向，不据此声称它们有相同的保存间隔、保留天数或默认隐私设置。

比较三条路径：

1. 复用 `SqlHistoryStore`：改动少，但现有按 SQL 去重、`strip()`、连接名称关联及直接覆盖文件，不适合精确、多标签的恢复语义。
2. 独立有界草稿存储（采用）：每个草稿独立身份与原始文本，失败/禁用/清空语义明确，保留原历史功能；增加少量存储和生命周期代码。
3. 完整脚本项目：适合长期归档，但文件命名、覆盖确认、外部修改等问题扩大首期，不是异常退出保护的前置条件。

当前 `AppSettings` 自动保存为 best-effort；草稿启停是隐私规则，使用独立严格持久化偏好，不把内存勾选成功冒充下次启动仍然关闭。`ConnectionManager.config(id)` 为内存查询；编辑器构造、自动补全预热及全局候选连接回退均需要隔离，不能仅传入 null 冒充无连接恢复。

## Global Constraints

- Java25 / JavaFX25 / JUnit Jupiter5.11.3；不增加第三方依赖，不改 JDBC、历史文件或导出语义。
- 仅使用合成文本、临时目录与替身网关；不读取、不修改、不暂存、不清理 `.testagent/`。
- 不新增网络、遥测、AI、数据库自动请求、密码存储或结果/事务持久化；不推送、打 tag、安装或发布。
- SQL 保留空白、换行和 Unicode 原文；不按 SQL 去重、不截断；编码/容量超限必须显式失败并保留已有版本。
- 草稿恢复不得调用 JDBC 会话创建、连接工厂、元数据、SQL 执行、提交或回滚；缺失连接不得回退到左侧当前连接。
- 文件格式、关闭状态、数据库调用计数与错误路径均须有独立证据；未实现、跳过、工具受限不得计为通过。

## 用户规则

- 默认启用本地草稿保护，首次编辑器和草稿管理页明确提示：“SQL 草稿仅保存于本机，可能含敏感文本；保留7天，可关闭或清空。关闭草稿不停止原有 SQL 历史记录。”说明格式编码不是加密，也不承诺安全擦除。
- 输入停止1秒触发快照；持续输入最多10秒触发一次。FX线程只取文本/身份快照；磁盘读写在独立串行工作器上。计时是调度目标，拥塞/断电前尚未成功保存的编辑可能丢失。
- 状态为“等待保存 / 正在保存 / 已保存 HH:mm:ss / 保存失败（可重试） / 草稿保护已关闭 / 草稿保护不可用”。只有最新编辑版本发布完成才能显示已保存；失败不阻断编辑。
- 每草稿 SQL 最多1MiB UTF-8；每个可空元数据字符串最多4096 UTF-8字节；最多100个草稿、正式草稿文件合计32MiB。超过限制保留旧草稿，提示手动复制/保存，不驱逐其他未过期草稿。
- 有内容后创建草稿；初始空编辑器不落盘。已保存草稿后来清空到空串，保存空串以反映真实清空，恢复列表显示“空草稿”。Unicode空白保留，不当作可丢弃空文本。
- 主动关闭标签和正常退出均保留最后成功版本，关闭前尝试刷新最新快照；取消关闭保持编辑与自动保存。P1 不把关闭标签解释为删除草稿。
- 恢复列表按修改时间降序，展示时间、连接名称/缺失提示、Schema及文本预览，正文只在显式选中后显示；不默认将 SQL 放在全局通知或日志。
- “恢复”只打开文本并沿用草稿ID，同一进程重复恢复已打开ID只聚焦已有标签。打开成功后不立即删除磁盘恢复点。原连接ID+类型匹配时保留目标提示，缺失/类型变化显示未绑定，执行前必须显式重新选择连接。
- “稍后”保留所有草稿；删除选中/清空全部有确认。清空是序列化屏障，旧任务不得写回已删除内容；已打开编辑器保留文本，只有之后的新编辑才重新产生草稿。
- 关闭自动保存先持久化关闭偏好并排空/作废在途旧保存，再确认UI状态；不默认删除已有草稿。设置写入失败继续显示失败，不能宣称已永久关闭。重新启用后捕获当前编辑器内容。
- 7天保留期以草稿内修改时间计算；启动或打开管理页在单写者锁内清理已知有效且未打开的过期草稿。未知版本/损坏文件不自动删除；清理失败可见并保留能读取的条目。

## 存储与错误边界

存储目录为用户配置目录下独立 `sql-drafts/`，通过注入 Path 测试。文件只用草稿UUID生成，绝不把连接名、Schema、SQL或导入字段拼进路径。

`SqlDraft` 为无凭据、不可变值：UUID、非负修改时间、可空连接ID、可空 PostgreSQL/Oracle 类型、可空显示名称、可空Schema、非null SQL。连接ID与类型必须同时存在或同时为空；名称仅展示，不用于连接匹配。`toString()` 仅含ID/时间/字符数，不包含文本或连接信息。

版本1为有界、严格UTF-8二进制格式：magic `0x44434452`、int版本1、UUID两个long、修改时间long，随后按连接ID/类型名/显示名/Schema/SQL顺序写入int字节长度+字节；可空值长度-1，SQL不可null。解析拒绝未知版本、负长度（除-1）、超长、截断、尾部垃圾、无效UTF-8、未知类型、Redis和不一致身份。内存输入中的非法代理字符拒绝编码，不能替换为问号。编码仅防格式混淆，不是加密或完整性认证。

单个草稿文件上限为1MiB+4×4096+64字节；在读取/分配前限制长度。草稿ID必须与文件名一致。损坏文件返回脱敏问题分类，仍加载其他有效文件；不静默当作空库，也不覆盖损坏/未知版本的同名文件。

使用应用级单写者 `FileLock`，同一配置目录的第二实例可以继续编辑，但草稿功能明确不可用，不偷锁、不并行覆盖、不自动重试写入。程序退出后锁由系统释放，不根据残留锁文件判断仍占用；锁文件不删除以避免并发锁文件身份变化。

更新采用同目录独占临时文件→写入并force→原子替换，不支持原子移动则失败，不降级为覆盖写。发布成功后才更新内存已保存状态；失败保留旧正式文件。失败临时文件尽力清除，无法清除必须报告。枚举不递归、不跟随符号链接，不删除无关文件；异常大量候选文件时停止扫描并禁用写入，保留原目录。

启停偏好使用同目录单独版本化文件及相同原子发布策略；其损坏或未知版本导致自动保存不可用，而非回退开启。普通草稿损坏不影响其他草稿恢复。未创建偏好文件时遵循默认开启并显示提示。

## 生命周期与并发

应用级 `SqlDraftCoordinator` 持有存储锁、单串行执行器和打开草稿映射；每个编辑器有独立草稿会话。快照带编辑revision和清空generation，过期的保存完成回调不能改变新状态。最多保留每个打开草稿的最新待写快照，避免持续输入无限排队。

删除/清空/关闭自动保存与写入同队列排序，调用完成后之前的写入不可能再发布；调用期间继续编辑的处理由generation明确判定。清空后不因关闭标签或定时器恢复同一旧文本，只有新的用户编辑或显式重新启用触发保存。

正常关闭在FX捕获草稿后，后台顺序刷新草稿并保留原事务关闭保护；草稿失败提示并允许重试/取消关闭或显式放弃本次未保存文本，不删除已成功版本。应用退出不得先关闭存储再关闭标签；拒绝退出后自动保存仍可用，部分退出失败不谎报成功。异常退出验证只终止独占合成测试实例。

恢复编辑器使用显式恢复模式，不通过“null绑定”复用全局候选行为。构造及恢复文本/Schema期间不创建专用JDBC会话，不安装自动元数据预热或全局连接跟随；在用户显式选择目标并执行后才进入正常查询链。恢复后的关闭也不得生成数据库请求。

## 实施分层与退出条件

| 子阶段 | 交付与依赖 | 必须证明 |
| --- | --- | --- |
| P1.1 格式契约 | SqlDraft / SqlDraftCodec，独立可测试 | 精确往返、边界与非法输入拒绝、日志脱敏；不声称已有文件恢复 |
| P1.2 本地存储 | 依赖格式；SqlDraftStore及严格偏好/锁/原子发布 | 保存后重开、旧版本保护、未知/损坏并存、多实例锁、容量、过期/删除边界 |
| P1.3 保存调度 | 依赖存储；SqlDraftCoordinator和会话 | 防抖/最大间隔、过期回调、失败重试、关闭/清空/禁用竞态，可控调度与真实磁盘组合 |
| P1.4 编辑器与恢复UI | 依赖前三阶段；独立恢复模式、状态、管理入口、设置、关闭流程 | 未执行文本保存/恢复、重复恢复、连接改名/删除/类型改变、零数据库调用 |
| P1.5 产品验收与集成 | 所有P1功能一起验收 | 合成重启/异常终止、完整回归、打包、独立审查、本地合并；发布门槛另记 |

每个子阶段有完整可执行实施计划和TDD证据，已完成项写入台账，不重复派发。P1的完成条件是整条用户路径及失败路径均被验证，不以某个存储单元测试通过代替。P2/P3/P4及此前发布门槛仍保留在总路线图。

## 自审

已明确保存时间、容量、默认隐私提示、清空与关闭不同语义、单写者规则、恢复身份、异常文件、失败保存与发布边界。独立存储是历史之外的新恢复机制，不修改历史记录策略、不伪称加密。分层是实施顺序，不缩小P1完整交付范围；用户常规决策授权已经满足，不等待重复设计确认。
