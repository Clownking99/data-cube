# P2.4 SQL 工作区显式恢复入口

日期：2026-08-31。基线 `9e5da57`，分支 `codex/sql-workspace-recovery`。按用户自主推进授权细化既有P2设计，不重复请求常规选型确认。

## 用户流程与选择

沿用P2“显式整组恢复”，不自动恢复会话。选择复用SQL草稿管理对话框：启动页新增“恢复 SQL 工作区…”入口，打开同一管理页；管理页新增工作区区块，先显示本地清单数量、可用/缺失数及记录偏好，再点击“恢复工作区”一次恢复整组。启动页入口只打开管理页，不隐式点击恢复；不因启动或展示提示就读取本地草稿或显示SQL。

另两个方案不采用：启动直接自动恢复有敏感文本突然显示的风险；单独再建工作区管理窗口重复P1草稿入口及生命周期。只增加明确入口/状态/操作，不重新设计整个应用、不引入新主题。

## 组件边界

1. `SqlWorkspaceRecoveryTabs`：FX同步恢复已解析Resolution，复用`SqlDraftRecoveryTabs.restore`，返回成功/复用/缺失/失败计数；管理排序、选择和新标签位置。不做磁盘I/O或连接解析。
2. `SqlWorkspaceManagerPane`：工作区区块，异步读取runtime清单和已验证草稿快照，展示数量/状态、恢复、刷新、记录开关、仅清空布局。pending/closed/generation约束防迟到更新。只消费上项与现有activity owner，无新线程/timer。
3. `SqlDraftManagerDialog`组合P1草稿区和工作区块，共享owner.observe的一次订阅；结束时同时close，writer仍由应用所有。
4. AppShell和WorkspaceStartPane只接入口和恢复工厂；保留原构造/静态helper兼容现有调用。SqlDraftUi提供已安装workspace adapter访问，binding提供按真实控件长度夹取位置；SqlWorkspaceUi提供短时同步恢复批次抑制，以免失败尝试制造新活动布局。

## 恢复算法

每次点击恢复先重新取得`runtime.refresh()`成功快照，再取`workspaceSnapshot()`；所有后续动作返回FX。普通refresh的completion可能先于busy-clear UI回调，因此必须显式Platform.runLater，不能直接thenCompose操作runtime。读取前后捕获`workspaceGeneration`；管理变更或关闭发生则本次结果失效，不创建编辑器。重复点击pending时不启动第二尝试。页面关闭后不创建标签、不更新可见状态。

正常可用清单（包括记录已关闭时的旧清单）经`SqlWorkspaceRecovery.resolve`按UUID解析。缺失/过期/损坏草稿不创建占位。清单不存在/空/不可读/未知版本分别呈现固定提示；坏清单不妨碍下方P1逐条恢复。不展示异常内容、路径、连接凭据。

FX批次内抑制activity/pulse捕获，每项按清单顺序调用原恢复工厂：已打开UUID只定位并计复用，不改正文/Schema/位置；新安装成功才按实际CodeArea长度分别夹取anchor/caret，保留反向UTF-16选择。失败不终止后续项；工厂abort依旧走现有屏障，不能吞掉所有权清理。

收集成功标签后只重排这些标签所占的槽位：例如当前`otherA,B,otherB,A,otherC`且恢复顺序`A,B`，变为`otherA,A,otherB,B,otherC`。未参与标签位置及相对顺序不变，新标签沿用工厂追加位置。使用真正permutation排序，不能remove/readd触发受管关闭。

原选中UUID成功则选择它；原选中缺失/打开失败则首个成功项；原选中null时保留恢复前的当前标签（仍存在时），没有原当前标签才选首个成功项。复用标签的原光标/内容不被重新应用。零成功保留原选择和原布局，不消费恢复点；至少一个成功后仅一次通知activity捕获最终布局。不删除清单或SQL，失败后可以再次点击。

## 管理操作与反馈

- 固定隐私说明：“工作区仅记录草稿引用、标签顺序和编辑位置；恢复会显示本地 SQL 草稿。清空工作区不删除草稿，SQL 历史独立管理。”
- “记录 SQL 工作区”偏好实际已读才显示开启/关闭；损坏偏好显示不可确认，不假定默认开启。只有草稿保护和工作区记录都开启才产生新清单；草稿关闭时仍允许显式恢复已有清单，说明不会记录新的布局。
- 开关通过`SqlWorkspaceActivity.setWorkspaceEnabled`，点击关闭立即暂停，落盘失败明确“本次已暂停，设置未保存，下次启动可能恢复”，不得刷新后假报已关闭/已开启；重新开启成功才恢复记录资格。
- “清空工作区”须确认，默认取消；文案说明只清空布局引用、不关闭编辑器、不删除SQL草稿、不是安全擦除。调用activity.clearWorkspace，成功后刷新为空；失败保留旧可恢复计数并明确未完成。保护中的未知/损坏清单不可强行覆盖。
- “刷新”显式重新读取；普通失败不循环重试。共享timer仅渲染状态、在初始化完成后启动一次初读。busy时恢复/管理禁用；其他P1管理完成或generation变更后刷新/失效缓存，不用旧快照恢复。
- 恢复完成保持管理页打开，显示“已打开 N，已定位 N，缺失 N，失败 N”；用户可以关闭管理页回到编辑器。部分失败同样保留成功项并提供再次恢复入口。计数必须来自真实成功结果，不把尝试数当成功数。
- 关闭对话框移除工作区/P1订阅，不关闭应用writer。原P1单草稿恢复成功关闭对话框的行为保持不变。

## 验收矩阵

真实临时store、实际FX/CodeArea/ContentTabPane及DraftConnectionProbe为主要夹具；不修改真实profile、不依赖外部数据库。第一批先RED再GREEN，后续逐行为迭代。

- 启动入口不调用回调直到点击，打开/关闭仍保持同一TabPane；草稿对话框有实际工作区区块。
- 有效多标签顺序/选中/反向UTF-16位置夹取；含已编辑重复标签和穿插非SQL标签，不覆盖复用内容/位置、不触发关闭；重复恢复无重复工厂。
- selected缺失、选中打开失败、selected null、有/无原当前标签；全缺失/全失败零创建零活动，部分失败准确计数且后续成功项保留。
- 缺失连接、同名异ID、同ID改名、类型变化、不存在Schema：正文保留，provider/session/metadata/network均0；不改变全局active connection。
- pending拒绝双击；读取后管理代次变更或页面关闭不建标签；初始化延迟后首次加载；读取失败可显式重试不假报空。
- 已关闭记录仍可恢复；草稿保护关闭仍可恢复且不写新清单；坏清单退回P1草稿恢复；损坏偏好不假报开启。
- 关闭记录成功、失败保持会话暂停、显式开启成功；清空取消无变更、清空成功只清布局不删草稿、失败提示与原恢复点保持。
- 对话框关闭释放订阅、迟到读取不更新；应用writer仍可用；原P2退出/取消屏障回归。
