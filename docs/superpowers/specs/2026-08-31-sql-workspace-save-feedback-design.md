# SQL 工作区保存失败反馈修订

整分支审查范围7710ecb..4cfda74发现：`SqlWorkspaceActivity`在普通读取/捕获/发布失败后锁存FAILED，停止自动重试；已有`statusText()`和`retry()`未被FX界面消费。管理页仅展示持久化记录偏好，刷新也不恢复保存。此为源码确认的接入缺口，实际失败回归尚待执行，不冒称已经复现。

按用户“后续无需我确认”自主推进授权，补足已批准P2的失败反馈，不新增自动重试策略。

## 选择

采用管理页内的独立“当前布局”状态和“重试保存布局”按钮：偏好是否开启、旧恢复点数量、本次布局是否保存分别呈现。另两种方式不采用：自动无限重试可能持续触发I/O故障；弹出模态错误会打断编辑，并不必要。不开新窗口、不增加timer/writer、不开启自动恢复或连接。

## 行为契约

- 工作区区块常驻当前活动状态：尚未开始、待保存、已保存、未保存/旧恢复点保留、已冻结、已关闭/本次暂停。固定脱敏文案，不显示SQL、路径或原异常。
- 读取旧恢复点的“刷新工作区”与发布当前布局的“重试保存布局”是不同动作。刷新不能谎报已恢复保存；点击重试也不能在实际发布完成前显示已保存。
- 重试从`SqlWorkspaceUi`适配器读取**当前已安装且已有草稿检查点**的标签/位置，交给原activity owner；不能直接重发可能过期的缓存，不打开第二store。
- 仅在FAILED、原runtime ENABLED且不busy，并且UI未disposed/closing/recovering时接受重试。disabled、session-paused、unavailable、closed、frozen、管理中和重复pending均拒绝。结构性不可用提示检查本机目录后重启，不暗中恢复资格。
- 捕获成功后更新当前候选，再显式释放失败锁存并驱动原pulse；状态由真正异步结果决定。捕获仍失败保留失败状态及旧恢复点，不发送旧候选冒充新布局。
- 不改变SqlWorkspaceActivity/Coordinator/store的代次、单写者、暂停或冻结规则；不影响恢复旧SQL草稿、正常关闭/退出的已有守卫。
- 管理页关闭后不再更新节点；writer与已接受任务仍按原应用生命周期结算。

## 证明与范围

先用真实store/FX/受管编辑器及故障注入复现写失败后的界面缺口。验证修复前红灯、修复后实际按钮重试保存最新位置、失败期间无timer重试、磁盘完成前不显示成功、再次失败保留恢复点及所有拒绝状态。随后完整非headless、整分支复审和新镜像/进程回归；已构建的旧镜像不能代表新修订。

仅独立工作树。`.testagent/`和main未提交SqlDraftStore内容不访问，真实配置/SQL/凭据不访问；没有数据库、网络、推送/tag/安装/发布。桌面通道本轮已两次失败，不再重试；修复不关闭该独立门槛。
