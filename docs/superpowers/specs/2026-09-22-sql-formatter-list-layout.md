# SQL 列表排版增强

状态：已实现，等待本地整合。

## 用户问题

复杂查询中的 `GROUP BY`、`ORDER BY`、`RETURNING` 和窗口 `PARTITION BY/ORDER BY` 经常包含多个表达式。全部挤在一行时，排序优先级和聚合维度难以审阅；但函数参数、`ROLLUP(...)` 等普通括号内的逗号又不应被误拆。

## 本轮行为

- 顶层 `GROUP BY`、`ORDER BY`、`RETURNING` 列表在逗号处换行，续行沿用河道缩进。
- `OVER (...)` 窗口定义中的分区和排序列表同样逐项换行。
- 仅在顶层/窗口上下文启用列表换行；普通括号深度内仍保持 `SUM(a, b)`、`ROLLUP(a, b)` 等行内表达式。
- 只调整空白和关键字大小写，不改变列表顺序、不执行查询。

## 明确不做

- 不根据列长度动态重排或推断最佳换行宽度。
- 不解析表达式优先级；复杂表达式仍以词法边界为准，执行前应人工检查。
