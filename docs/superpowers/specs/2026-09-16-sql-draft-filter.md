# SQL 草稿摘要筛选

基线 main `04a9600`。草稿管理只有按时间排列的列表，最多 100 份恢复记录逐条翻找不便。本轮补齐局部筛选，属于自主选择的工作流改善假设，不宣称已获得用户效率证据。

- 在草稿管理区域增加筛选框、清除筛选、显示数量及范围提示。忽略首尾空白和大小写，按字面匹配连接摘要、Schema 摘要、SQL 摘要；元数据沿用当前列表各前 80 个 UTF-16 单元、SQL 沿用前 120 个单元（控制字符显示为空格）。不搜索日期、ID、未显示元数据尾部或后续 SQL，不新增全文索引。
- 只筛已读取的快照，不读取文件、修改存储或触发数据库/剪贴板。查询最多 256 UTF-16 单元，超长整体拒绝并明确提示。条件仅当前窗口，清除后恢复最新快照的时间倒序，新窗口默认空。
- 输入不默认选择、恢复或删除。原选项仍匹配时保留同一草稿和正文选区；被排除时清空选择/预览并禁用恢复/删除所选，不按位置换成另一份。刷新快照后按 UUID 复核选择并使用最新记录内容。
- Ctrl+F 聚焦并全选筛选词，↓ 明确进入候选列表，筛选框/列表 Enter 只恢复已选项；预览 Enter 不触发恢复。保留外层窗口原有关闭语义，不让删除按钮成为默认确认。
- 初始化、忙碌、存储不可用及关闭继续使用原准入规则。忙碌期间可修改本地筛选，完成后应用最新条件；关闭/禁用区域不再处理新筛选或键盘动作。部分失败提示不因筛选被抹掉。
- 「删除所选」仍只针对已选 UUID；把按钮和确认改为「清空全部草稿」，明确包括被筛选隐藏的记录，默认取消。不改变原存储清空范围、不加入“批量删除匹配项”。
- 明暗及窄窗验证新输入、提示、数量和操作控件可读，范围文字不会误称完整 SQL 搜索。输入查找词不上传、不持久化、不记录遥测。

实施顺序：独立 worktree → 缺少入口 RED → 单个管理 Pane 实现与直接状态测试 → 全量/开发镜像 → 合成隔离桌面 → 差异审查、提交、本地快进 main。复用真实协调器及内存 backend，不创建通用测试流水线工件，不读取/修改/暂存 `.testagent/`；不触碰真实草稿、连接、业务 SQL 或系统剪贴板，不推送、不打 tag。
