# 历史 SQL 显式选择连接

基线 `980384c`，独立 `codex/sql-history-connection`。已核实 AppShell 的历史载入创建独立空 SessionContext，但未安装选择器，左侧连接变化也无法为其提供目标。本轮打通历史找回后的继续工作流程，不增加自动执行入口。

## 范围

- 历史 SQL 使用与脚本文件相同的被动连接模式，提供“选择脚本连接”。载入时 SQL 和 schema 提示保留；原历史连接名只用于标题，并标明“历史”，不按名称查找或自动关联保存的连接。
- 每个历史标签使用独立会话，初始无目标且执行禁用；明确选择 PostgreSQL / Oracle 后只保存稳定 ID/type 意图，不创建 JDBC 会话、预热元数据或发网络请求。全局树选择不改变历史标签目标，Redis 不参与选择。
- 取消保留文本、schema、已有目标和文件状态；目标删除/类型变化不能回退到同名连接。沿用现有选择器对失效、关闭、忙碌以及首次会话操作锁定的检查。
- 沿用受管标签、文件和草稿生命周期：初始为干净的未绑定文件；编辑后标记未保存，首次保存另存为；选择目标及编辑进入既有草稿检查点。载入/选择时不改历史格式或条目，不保存凭据/文件路径到草稿；正常关闭和执行仍沿用原有历史记录规则。SQL 显示和 schema 首尾空白处理沿用原有编辑器语义。
- 不修改 F5、事务、执行安全检查或全局连接管理；执行前需核对当前连接、schema 和 SQL。

## 顺序

先对原载入路径抽取小型 SqlHistoryTabs 边界并证明缺少连接入口红灯，再启用被动工厂和已有选择器。测试技能用于聚焦流程的状态矩阵和 Java/JUnit 断言，不套用额外多代理/中间文件步骤。覆盖同名、取消、失效、草稿/文件、失败清理；全量测试、开发镜像、隔离桌面验收后提交并快进 main，不推送/tag、不碰 `.testagent/` 或真实连接/历史。
