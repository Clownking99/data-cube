# 查询结果恢复列布局

## 产品决策

查询结果已有列隐藏、重排、拖宽和查找，但“显示全部列”仅恢复可见性。增加“列”菜单靠前的“恢复列布局”，让用户在查看宽表后回到本次查询最初的列顺序、列宽与可见状态，不新增工具栏按钮或快捷键。属于常规自主推进，不涉及数据库写入或发布。

## 范围与实现

- 仅 `SqlResultColumnMenu` 管理的当前查询表格；基线为首次接收到这组列对象时的顺序、初始建议/实际宽度、可见性（包括序号列）。先完成初始表头布局；后台标签尚未挂载到 Scene 时，在首次布局后补齐实际宽度，切换结果/关闭取消旧回调。以列对象身份区分同名列，不按名称匹配。
- 本地筛选、行排序、紧凑行、注释模式和菜单刷新不重设基线；新列组、离开查询或关闭释放旧基线。切换批量结果沿用既有重建列行为。
- 恢复不重新取数、不修改 SQL/源文件或结果值；保留当前行筛选、行排序及仍有效的选中单元格。导出继续反映恢复后的可见列及顺序，行范围不扩大。
- 初始布局或无查询列时不可用。忙碌、禁用、关闭、列组替换后拒绝旧动作；保留“显示全部列”的单独行为。
- 不持久化布局，不提供撤销列布局、自动内容测量或跨结果通用布局，不改数据库与执行路径。

## 验证与交付

在独立 `codex/result-column-reset` worktree 先写缺失入口/行为回归，覆盖重排+隐藏+缩放组合、筛选及排序保留、重复名称、零行/单列、旧动作隔离、动态刷新与新批次。检查现有列查找与导出兼容性；定向和全量测试、开发打包通过后使用隔离合成数据做 Windows 原生交互验证，再本地合回 main。桌面不可用则如实保留待验。无推送、tag 或版本升级。
