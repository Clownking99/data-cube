# DataCube：查询结果导出范围与文件保护设计

日期：2026-08-30

设计基线：`c811802ce89884af551193b37947e35bac21243e`。设计分支：`codex/safe-result-export`。

## 1. 目标与代码依据

让用户筛选查询结果后，能够明确知道“将带走哪些行、哪些列，是否包含预览值”，并在导出失败时保留已有文件。

设计基线代码存在三个衔接点（以下为实施前的问题，不是修复后行为）：

- `SqlEditorPane.copyResultSelection` 按 TableView 的当前可见行列与排序复制；`exportAs` 和 `onCopyInsert` 则读取 `activeResult.rows`，没有应用本地可见行索引和列顺序。
- `exportAs` 直接把用户选择的目标路径交给 writer，发生异常后调用 `deleteIfExists(out)`；覆盖已有文件时缺少“成功后才替换”的隔离。
- `ImmutableResultValue` 为大文本、二进制和聚合提供有界展示；这些展示不一定是完整原值，也不等价于可用于 INSERT 的 SQL 字面量。

以上为本地源码分析，不代表用户访谈或真实数据库复验。现有结果筛选、连接所有权、取消与关闭约束继续适用。

执行修正（2026-08-30，用户已认可）：实施中确认旧路径的长 CLOB 并未保留上述预览包装，而是返回截断后的普通字符串。本轮已修复共享冻结阶段的 CLOB 完整性标记，补充边界与资源清理回归；导出本身不重新读取 JDBC，也不扩大结果行数。

该修复复用 SQLXML 已采用的流式文本冻结路径：保留最多 500 字符预览，同时遍历初始文本流记录总长度与内容指纹。内存保留有界，但首次读取成本与 CLOB 长度相关；真实数据库的大字段加载耗时仍需专项验证。完整的短文本仍作为普通字符串，长文本明确展示为预览。

## 2. 方案与范围

采用**范围确认 + 不可变导出快照 + 临时文件原子发布**。

只修改默认行来源的方案改动较小，但不能解决旧文件保护及摘要被误当原值的问题。新增全量重查、导出任务中心或持久化任务队列则引入数据库与生命周期的新边界，本轮不采用。

### 纳入

- SQL 编辑器查询结果文件导出：现有 XLSX、CSV、SQL、HTML、XML 格式。
- 顶部及右键“复制 INSERT”，复用同一范围与值校验规则。
- 导出前范围、数量、行截断和特殊值提示。
- 只写本次唯一临时文件，成功后才发布至目标路径。
- 任务拒绝、写入失败、发布失败、关闭及迟到回调的处理。

### 不纳入

- 连接树的整表导出、`pg_dump`、迁移、Redis 导出及它们的文件生命周期。共享 writer 的既有调用不被悄悄改变。
- 自动执行原 SQL、扩大读取上限、获取数据库总数或补取大字段。
- 新增格式、导入、备份恢复承诺、通用跨数据库 SQL 字面量重写。
- 全局任务中心、导出历史、格式偏好持久化或工作台改版。
- 重写 CSV 公式处理策略；文件发布安全不等于任意导出数据在其他软件中打开或执行均安全。
- 已有 TSV 选区复制行为保持不变，不增加范围弹窗。

## 3. 用户行为

### 3.1 轻量范围确认

用户选择现有导出格式后，先显示范围确认，再进入系统保存对话框；复制 INSERT 使用相同确认组件但不选择文件。

| 范围 | 行来源与顺序 | 列来源与顺序 |
| --- | --- | --- |
| 当前筛选结果（默认） | 当前 TableView 中全部可见行，遵循当前排序；不是仅选中的行 | 当前可见数据列的显示顺序，排除 `#` 序号列 |
| 全部已加载行（加载顺序） | 本次活动结果快照的全部保留行，使用加载顺序，忽略本地条件和搜索 | 同一份当前可见数据列及顺序；不是自动补回隐藏列 |

“全部已加载”只指活动结果，不指数据库全量，也不自动切回之前缓存的原始结果。确认页明确写出行数、列数、范围名称和顺序，避免用户把行范围选项误解成全表备份。

- 每次打开默认选择“当前筛选结果”，不记忆上次的扩大范围选择。
- 当前筛选为零行时显示“当前筛选结果为 0 行”，禁用该范围的继续按钮；绝不自动回退导出全部行。其他范围有数据时仍可手动选择。
- 当前没有数据列或活动结果不是查询结果时不可导出。首版不新增仅表头文件功能。
- 取消任意确认或保存对话框不提交后台工作、不触碰文件或剪贴板。
- 复制 INSERT 的目标表从本次快照的原 SQL 推断，无法确定时保留人工指定；不得读取后来改变的编辑区或 `lastQuerySql` 来替换已确认目标。

### 3.2 行截断与值表示

分开呈现两种事实：

1. **结果行截断**：依据快照的 `truncated`，提示“仅包含已加载结果，数据库中可能还有更多行”。不得显示虚假的数据库总数，也不得读取当前设置重算历史保留行数。
2. **值不是可无损导出的原值**：大字段预览、特殊二进制/聚合展示、未知类型等，通过结构化能力判断，不解析 `toString()` 中的省略号或后缀。

非 SQL 文件遇到特殊值时，显示涉及的单元格数量及“将导出当前展示，不代表完整原值”，要求用户明确确认后才能继续；文件保留展示中已有的截断/类型标记。提示不复述单元格内容。普通标量继续保留现有格式能力，例如 XLSX 的数字和布尔单元格，不一律先转成字符串。

SQL 文件和复制 INSERT 采用更保守规则：只接受现有生成器能明确处理的完整标量；`ImmutableResultValue`、未知对象、非有限数字以及不能证明正确序列化的值整次阻止。即使某个二进制/数组的展示没有截断，也不能仅凭完整展示就把它当 SQL 原值。

禁止静默丢弃问题行、替换成 NULL、把摘要拼入 INSERT，或为绕过限制自动重新查询。行数截断本身不禁止输出完整标量的已加载子集，但必须显示子集提示。

SQL 产物仍是供用户审阅的文本，不在本轮自动执行，也不承诺目标表约束、字段别名映射或跨库往返兼容性。

### 3.3 搜索、快照与并发

打开范围确认前，在 FX 线程提交尚在防抖中的搜索文字，取消对应延迟回调，再捕获候选快照。

这次搜索提交不得顺带重置用户的列顺序与排序定义；需要刷新本地结果时保留这些展示设置，快照对应“最新搜索 + 原有排序/列顺序”。确认或取消导出本身不改变结果表的展示设置。

快照固定活动结果、原 SQL、当前可见行顺序、可见列位置及标签、行截断事实和两种范围的计数。确认页展示的是这份快照；用户确认后后台不再读取 TableView、当前设置、当前连接、当前 SQL 或筛选状态。

值对象复用已经冻结的结果数据；新建的是不可变的行列投影及请求，不重新读取 JDBC，不复制多份大字段。短行按对应位置补 NULL，重复值行按位置保留，不按内容去重。

一次编辑器最多一个文件导出任务在途，重复点击不会启动第二次写入。导出只固定其输入，不阻止用户随后查看其他结果；新查询出现后，旧导出的完成回调不得覆盖新查询的结果、选择或状态提示。

## 4. 文件发布与生命周期

### 4.1 文件所有权

- 在用户选择的目标文件同目录创建唯一临时文件；writer 只接收临时路径。
- 新文件及覆盖文件统一在 writer 完成且所有流成功关闭后，才尝试原子发布。
- 若平台或文件系统不支持所需的原子发布，报告无法安全保存并保留旧目标，不退化为“先删目标再移动”或直接覆盖写入。
- 用户取消、写入失败、发布失败时，只清理本次创建且尚未发布的临时文件，绝不把目标文件当临时文件删除。
- 临时文件清理失败要明确报告，保留准确路径供人工处理；不递归清理目录，不扫描删除其他导出文件。
- 目标为目录、符号链接或其他不支持的文件类型时拒绝，不跟随链接覆盖其他位置。
- 本进程对同一规范化目标路径的导出进行互斥；用户确认后若发现目标已被其他任务创建或改变，拒绝发布并要求重新选择/确认。
- 覆盖已有文件必须有明确确认；选择目标并确认时记录其存在性、文件身份及大小/修改时间，发布前核对。目标此前不存在而发布前出现时，不沿用对不存在文件的确认去覆盖新文件。

上述检查减少覆盖竞态，不承诺抵御其他进程在文件系统检查与原子操作之间持续恶意替换路径，也不承诺断电持久化。验收以支持的本地文件系统能力与可复现失败注入为依据。

### 4.2 关闭和完成状态

复用应用级 `FxTaskRunner` 与编辑器任务作用域，不创建全局执行器。文件发布还需独立的操作令牌，不能仅靠抑制 UI 回调表示取消。

- 写入开始前、循环写行期间及最终发布前检查取消/中断。
- 关闭编辑器封住新导出并取消未提交的任务；发布和取消通过同一个终态门禁竞争。
- 取消先被接受时，不再发布，清理临时文件；原子发布已经提交时，不删除已完成目标或谎报“已撤回”。
- 关闭后不更新该编辑器 UI。旧导出完成也不能重建结果表。
- 关闭后发生临时文件清理失败，通过受控诊断记录精确临时路径和固定失败阶段，不重新打开已关闭页面，也不记录原始异常或数据值。
- 成功只在文件实际发布后报告；复制 INSERT 只在剪贴板 writer 返回成功后报告，失败保留原剪贴板状态的承诺以平台能力为限。
- 提交被拒绝、写入失败、发布失败分别恢复可操作状态，使用固定可理解的提示；不展示 SQL、单元格值、连接属性或原始异常。路径仅用于本地保存/临时文件处置反馈。

## 5. 组件边界与数据流

组件名为建议命名，实施计划可结合现有结构调整，但职责不得合并回单一巨型事件处理器。

- **ResultExportSnapshot / ResultExportScope**：纯 Java 不可变投影；输入冻结结果和明确的行列位置，输出选定范围及准确计数，不依赖 JavaFX/JDBC。
- **ResultExportValuePolicy**：判断值可直接导出、仅可展示导出或不可生成 SQL；使用结构化类型信息，不通过展示文本猜测完整性。
- **ResultExportOptionsDialog**：复用现有主题的轻量确认；只展示快照摘要并收集范围/预览确认，不读取数据库。
- **SafeResultFilePublisher**：拥有唯一临时文件和发布门禁，接收受控 writer、目标和取消令牌，负责精确清理、互斥与终态。
- **SqlEditorPane 接线**：FX 侧提交待处理搜索、捕获展示顺序与来源，确认后提交已有任务作用域；复制 INSERT 与文件导出共享范围和值策略。

数据流：当前展示 → FX 提交搜索并捕获快照 → 范围/特殊值确认 → 选择目标 → 后台写唯一临时文件 → 关闭流与终态检查 → 原子发布 → 有效所有者接收状态。

现有 `ResultExporter`、`XlsxWriter` 和 `InsertSqlGenerator` 保持格式层职责。文件发布策略在其外侧组合，避免把本轮查询结果规则施加到未纳入范围的整表导出或迁移调用。

| 导出内容不会随后续 UI 变化而改变 | 可控后台阻塞期间更换结果/筛选/列顺序，输出仍对应已确认快照 |

| 复制 INSERT 行为一致 | 顶部/右键共用快照与校验；取消及被拒绝不调用剪贴板 writer，写入失败不报成功 |

## 7. 自审与交付边界

- 两种范围均定义了行源、列源和顺序，默认行为符合用户已认可方向。
- 行截断、值展示、SQL 可序列化性分别处理，不承诺补取或恢复丢弃的数据。
- 文件写入、发布、取消、UI 完成各有所有者和明确终态；不删除旧目标补救失败。
- 设计不触碰 `.testagent/`，不自动推送、打 tag 或重开数据库重查范围。
