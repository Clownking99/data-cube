# SQL 脚本文件工作流设计

## 1. 背景与目标

DataCube 已能通过 SQL 历史、草稿和工作区恢复保护编辑内容，但尚不能把 SQL 编辑器作为普通 `.sql` 文件编辑器使用。用户无法明确打开、保存或另存脚本，也看不到文件是否有未保存修改。

本阶段交付一个独立、可验证的文件工作流：打开 `.sql`、保存、另存为、未保存标记、最近文件和外部修改保护。文件内容只进入编辑器，不自动连接数据库、不读取元数据、不执行 SQL。

## 2. 方案选择

比较三种实现：

1. 直接把文件读写写进 `SqlEditorPane`：改动快，但会继续扩大已经复杂的编辑器，并把文件安全、UI 和 JDBC 生命周期混在一起。
2. 独立脚本文档模型、安全文件存储和轻量 UI 协调器：边界清楚，文件规则可脱离 JavaFX 测试，并能复用现有受管标签和虚拟线程。
3. 一次完成脚本项目、目录树、收藏和搜索：覆盖更广，但会引入目录监听、重命名、批量操作和项目状态，超出本阶段。

采用方案 2。完整脚本项目保留为后续候选。

## 3. 用户体验

- 顶部工具栏新增“SQL 文件”菜单，包含“打开…”、最近文件和“清空最近记录”。
- SQL 编辑器工具栏新增“保存”和“另存为”。默认快捷键为 `Ctrl+O`、`Ctrl+S`、`Ctrl+Shift+S`，纳入现有快捷键设置。
- 文件标签使用文件名；编辑内容与最近一次成功打开/保存的内容不同时在标题末尾显示 `*`。
- 普通 SQL、历史或草稿标签第一次保存时进入“另存为”；成功后成为文件标签。
- 打开文件始终创建新 SQL 标签，不自动绑定连接，也不执行内容。用户后续可按现有方式选择连接并执行。
- 关闭有未保存文件修改的单个标签时提供“保存 / 不保存 / 取消”。保存失败或冲突时标签保持打开。
- 应用整体退出沿用现有 mandatory close：不隐式覆盖文件；未保存文本继续由草稿/工作区恢复保护。恢复后的文本保持草稿身份，用户显式保存后才重新绑定文件。

## 4. 文件契约

### 4.1 读取

- 只读取普通文件，拒绝目录和符号链接。
- 最大文件大小为 8 MiB；超限直接提示，不截断。
- 使用严格 UTF-8 解码；允许并移除一个 UTF-8 BOM。非法字节提示失败，不使用平台默认编码替换字符。
- 保留文件中的文本和换行；打开后不自动格式化。
- 读取前后比较文件版本，若读取期间被修改则失败并提示重试。

### 4.2 保存

- 写入 UTF-8、无 BOM，内容取用户点击保存时的不可变快照。
- 先在目标目录创建应用拥有的临时文件，完整写入并关闭后，再以原子替换发布；不支持原子移动时拒绝保存并保留旧文件。
- 已打开文件保存时，使用打开或上次成功保存后的版本作为前置条件。若外部程序修改、替换或删除目标，返回冲突并且不覆盖；用户可重新打开或另存为。
- 另存为覆盖已有文件前由 DataCube 明确确认。确认后仍重新捕获版本，并在最终发布前检查，防止确认后的竞态覆盖。
- 失败消息只暴露固定阶段（目标无效、读取、编码、冲突、写入、发布或清理）和用户选择的目标路径，不传播文件内容、SQL 或底层异常细节。

文件版本由规范化绝对路径、文件标识、大小、修改时间和创建时间构成。成功保存后返回新版本，成为下一次保存的基线。

## 5. 组件边界

### `SqlScriptFileStore`

阻塞式纯文件组件，负责严格加载、版本检查、临时文件和原子发布。不得在 JavaFX 线程调用。

### `SqlScriptDocument`

纯内存文档状态，保存当前路径、基线文本和文件版本；根据当前编辑文本计算 dirty、标题和保存前置条件。它不读写磁盘，不持有 JavaFX 控件。

### `RecentSqlFiles`

在 `~/.datacube/recent-sql-files.txt` 中最多保留 10 个规范化绝对路径，最新在前、去重。仅存路径，不存 SQL、连接、Schema 或凭据；写入失败不阻断编辑。用户可清空列表。

### `SqlScriptFileController`

每个 SQL 标签一个轻量协调器，连接编辑文本、标题、保存按钮、文件选择器和后台任务。它只通过公开回调更新标签标题，不参与 JDBC、草稿存储或结果导出。

### `AppShell`

只负责“打开文件/最近文件”入口和创建新 SQL 标签。读取在应用级虚拟线程执行，成功后在 FX 线程安装标签；失败时显示固定、可操作的提示。

## 6. 并发与关闭

- 每个标签最多一个文件操作；操作进行中禁用保存和另存为，迟到回调须校验操作代次和标签仍存活。
- 保存成功只在当前文本仍等于保存快照时清除 dirty；保存期间继续编辑则保留 `*`。
- 普通关闭先处理文件 dirty 决策，再进入现有 SQL 会话/草稿关闭守卫。取消或保存失败不得启动资源销毁。
- mandatory close 不等待文件选择器或覆盖确认，也不写文件；现有草稿关闭屏障继续负责恢复点。

## 7. 最近文件

- 成功打开或保存后置顶；仅选择文件但失败不加入。
- 最近项不存在、不是普通文件或无法读取时显示错误；不自动扫描其他目录，也不猜测替代路径。
- 菜单显示文件名和父目录提示，最多 10 项；清空只删除最近路径记录，不删除脚本文件或草稿。

## 8. 测试与验收

自动化至少覆盖：

- UTF-8/BOM、非法编码、8 MiB 边界、目录/符号链接拒绝。
- 新文件与覆盖保存、原子移动失败、写入失败、确认后目标变化、外部修改/替换/删除冲突、旧字节保留、临时文件清理。
- 文档 dirty/title、保存期间再次编辑、另存为重新绑定、恢复草稿不自动绑定。
- 最近路径去重、上限、损坏记录、清空和失败不影响编辑。
- 打开不触发连接/provider/session/metadata/network，快捷键和菜单入口存在。
- dirty 标签关闭的保存/不保存/取消，以及保存失败保持标签。

最终运行完整测试和 `jpackageImage`，并在隔离目录用实际 `DataCube.exe` 验证打开、编辑、标题 `*`、保存、另存为、外部修改冲突和最近文件；不得访问真实 SQL 文件、数据库或用户配置。

## 9. 非目标

- 文件夹/项目树、文件监视自动重载、收藏夹、全文搜索、Git 集成。
- 非 UTF-8 编码选择、自动格式化或换行转换。
- 自动执行、自动连接或从文件内容推断目标数据库。
- 把文件路径写入草稿或工作区格式；不修改现有恢复文件兼容性。
