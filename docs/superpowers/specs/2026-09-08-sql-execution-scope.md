# SQL 执行范围可见性

## 产品决策

基线 `main` / `df36e2c`。当前执行和执行计划取“非空白选区，否则全文”，但执行按钮固定显示“执行”。
查找会改变选区，用户仅凭按钮不能确认下一次执行的范围。本轮优先消除这个可从代码验证的歧义，
不宣称已有用户访谈、误执行统计或任务耗时改善。

- 执行按钮按当前范围显示“执行选中”或“执行全部”，保留并即时更新已配置快捷键。
- 编辑器底部显示光标行列、选区长度和执行范围。仅含空白的选区明确提示仍执行全部，
  保持原有 `String.trim().isEmpty()` 语义；不擅自增加“执行当前语句”或改变 F5 行为。
- 行列从 1 开始，列和选区长度按 UTF-16 单元计（Tab 为一个单元），提示中说明。
- 提示与执行/执行计划使用同一个范围判定。查询计划原有“只处理范围内第一条语句”规则保持不变。
- 光标、键盘/反向选区、查找定位、正文修改和快捷键改绑后同步更新；状态只描述下一次操作，
  不改写运行中已捕获的执行快照。不显示 SQL 正文或增加日志/遥测。
- 状态条在明暗窄栏下换行，继续保留正文最小高度；不新增工具栏按钮。
- 不改变文件、草稿、会话、风险确认、只读、事务、查询结果和关闭语义；关闭时移除新监听。

## 实施与验收

1. 抽取与旧逻辑等价的范围判定，验证空/普通/空白/反向/多行/Unicode/非法边界。
2. 独立只读状态组件、快捷键变更通知、编辑器接入；验证标签隔离、关闭后不更新和无文本副作用。
3. 实际执行接缝校验、查找定位及明暗 480/640/880px 布局回归；定向、全量、开发镜像。
4. 用隔离配置和合成 SQL 进行桌面验收；工具受限则如实记录。完成后本地合并 main，
   不由“继续推进”额外推断推送、tag 或 Release 授权。
