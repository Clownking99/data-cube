# SQL 美化数组与下标布局

## 范围

当前数组方括号不参与布局状态，SELECT 中的数组逗号会错误触发外层列换行，连续下标带多余空格。只改 SqlFormatter，补齐数组构造、嵌套数组、下标、切片和数组类型后缀的排版；不改 SQL 执行、连接、编辑器操作或文件保存。

## 规则

- 识别 ARRAY 关键字，输出 `ARRAY[1, 2]`；方括号内部逗号行内排列，结束后恢复外层 SELECT/ORDER/GROUP 等列表规则。
- 方括号以独立类型进入现有定界符栈；其内部像普通括号一样隔离外层子句，但仍允许 CASE、子查询、窗口使用既有布局。子查询/窗口返回后恢复外层括号深度。
- 连续下标和类型后缀紧贴前一表达式，如 `matrix[1][2]`、`integer[]`；嵌套数组的行内逗号后保持一个空格。
- 切片如 `a[1:3]`、`a[:3]`、`a[1:]` 紧凑排版。冒号只在当前直接方括号层处理，不改变函数参数、绑定和类型转换规则；原本分开的两个冒号不能拼成 `::`。
- 引用和注释中的方括号不参与结构；注释的换行边界不能移除。不同类型的闭合符号不能误弹出其他定界符栈帧，不将不完整输入当作语法有效的 SQL。

依据 [PostgreSQL 数组说明](https://www.postgresql.org/docs/18/arrays.html)和[数组表达式](https://www.postgresql.org/docs/18/sql-expressions.html#SQL-SYNTAX-ARRAY-CONSTRUCTORS)选择排版。方括号按数组/下标解释，不新增 SQL Server 方括号引用标识符支持；不验证数组维度、操作数类型或真实数据库结果。
