# 当前 SQL 文本替换

## 产品决策

基线 main `ea9c867` 已有离线文件选择目标和字面查找。本轮补齐复用脚本时修改重复文本的步骤；
这是基于现有流程的产品判断，不声称有用户访谈或耗时统计。

- 在查找栏增加“替换…”入口；可改绑的 Ctrl+H 直接展开。查找默认仍只读，替换区初始折叠。
- 仅当前编辑器、字面匹配、沿用大小写选项；无正则、跨文件、结果集替换或语义重命名。
- “替换当前”仅替换当前精确选中的有效匹配；否则先用上/下一个定位，不猜测待改范围。
- “全部替换”仅对完整匹配结果生效；超过查找的 10,000 处上限时拒绝，不做部分替换。
- 替换文本最多 4,096 个 UTF-16 单元，空文本表示删除；生成正文上限 8 Mi UTF-16 单元，
  这是编辑内存边界，不代替 SQL 文件保存的 UTF-8 8 MiB 上限。$、反斜杠等均按字面处理。
- 后台生成全部替换候选，FX 发布前核对代次、正文、可编辑/关闭状态及当前标签焦点；
  编辑、查询/大小写/替换输入变化、隐藏、切走标签或关闭后，旧结果不得改变 SQL。
- 一次替换作为独立撤销单元，与前后键入隔离；内容未变化时不增加撤销项。
- 替换只修改当前内存正文，沿用文件 dirty、手动保存、草稿检查点和关闭保护。
  不自动连接、加载元数据、执行 SQL、写 SQL 文件、改变目标或事务状态。
- 控件随宽度换行；明确呈现替换数、超限与失败，不显示后台异常或原始 SQL。

## 实施与验收

1. 纯文本替换候选与容量/取消测试；扩展现有查找栏、保持查找导航契约。
2. 接入快捷键及编辑/关闭门禁；真实 CodeArea 撤销、旧任务、无操作、离线文件和草稿回归。
3. 定向测试、全量和开发镜像打包；隔离合成 SQL 桌面验收，记录未完成项。
4. 审查后本地合并并推送 main、核对同 SHA CI；不打 tag、不发布或访问真实数据库。
