# P2 SQL 工作区恢复设计

日期：2026-08-31。起点：main `7710ecb526d10a22e3fbff65367c50b04e44ed9d`，独立分支 `codex/sql-workspace-recovery`。P1 已整合；本文件不是 P2 完成声明。

## 目标与选择

用户下次启动后能一次找回上次正在编辑的 SQL 标签、顺序与编辑位置，不必从草稿列表逐个寻找。恢复的是编辑状态，不是数据库会话。

参考事实（2026-08-31 查阅）：[DataGrip 系统设置](https://www.jetbrains.com/help/datagrip/system-settings.html)提供重新打开项目选项；[连接说明](https://www.jetbrains.com/help/datagrip/connecting-to-a-database.html)说明启动不建立数据库连接。这里借鉴工作连续性与连接分离的原则，不声称产品之间保存格式或隐私策略相同。

方案比较：

1. 每次启动自动重建全部标签：步骤少，但会立即显示历史 SQL，并放大损坏/大工作区的启动影响。
2. **启动页提示，显式一键恢复（选用）**：减少逐条恢复操作，同时保留内容显示时机的控制；也在 SQL 草稿页提供入口，避免开始工作后入口消失。
3. 完整会话/结果集快照：占用大、涉及业务数据及事务歧义，超出本阶段范围。

按用户“后续无需我确认”的授权记录此选型，不等待例行确认。以后可单独评估启动自动恢复，不在首期暗中开启。

## 全局边界

- Java 25、JavaFX 25、JUnit Jupiter 5.11.3、Gradle wrapper 9.2.0；不添加依赖。
- `.testagent/` 属于用户，不读取、不修改、不暂存、不清理。
- 不读取真实配置、凭据、SQL 历史、业务导出；只用合成数据和独占临时目录验收。
- 不自动连接、预热元数据、执行 SQL、提交/回滚事务或重放 Redis 命令。
- 工作区清单只含草稿 UUID、顺序、选中项、时间、光标/选择锚点；不复制 SQL、连接身份、Schema、凭据或结果集。连接身份与 Schema 由 P1 草稿提供。
- 恢复使用稳定连接 ID 与数据库类型；同名不同 ID 不替换，删除/类型变化保持待确认，改名使用现有 ID，Schema 不在恢复时查询验证。
- 不访问外部数据库或上传内容；不新增遥测。不推送、tag、发布、安装或升级。
- P2 完整验收和整分支审查通过才本地合并 main；基础模块完成不等于用户入口完成。

## 产品语义

### 记录与恢复范围

- 记录成功保存过的 SQL 草稿标签，最多 100 个，顺序与界面一致。新建后一直空白、尚无有效恢复点的标签不制造空草稿占位。
- 清空已有 SQL 后成功保存的空草稿仍可恢复。未经保存的最新输入不能被宣称已保护。
- 清单中的选中 UUID 可以为空，表示当时没有选中可恢复 SQL 标签（例如选中结果页）；不把其他类型标签伪装成 SQL。
- 恢复前通过已验证草稿快照按 UUID 解析；不存在/损坏/过期而不在快照中的引用按原顺序计入缺失列表，不查找同名内容、不创建空白替代。
- 有效条目按清单顺序恢复。原选中项缺失时选择首个成功解析项；原选中项为空时不指定原选中 SQL。无可用项时不创建标签。
- 已经打开相同草稿时复用现有标签，不覆盖用户正在编辑的内容及光标；只重排此次恢复所涉及的 SQL 标签，其他标签相对顺序不变。部分创建失败保留已成功项并呈现已恢复/缺失/失败数量。
- 光标和选择锚点以编辑控件 UTF-16 偏移保存；真正装载文字后按控件长度夹取，不把持久化的偏移当成 SQL 字节索引。保留反向选择。解析阶段不裁剪、不换行归一化原始 SQL。
- 一次恢复失败不消耗旧快照。启动时未触及工作区且直接退出，也不能用空窗口覆盖旧快照；新建 SQL、明确关闭、成功恢复等用户动作之后才建立本次活动工作区。

### 正常关闭、退出与异常

- 用户关闭单标签：沿用现有关闭确认；只有真正移除后才从本次活动清单移除。关闭取消不移除。
- 退出应用：在批量关闭前冻结顺序、选择和位置。草稿各自完成关闭保存后，提交该退出清单，再关闭 writer；不能在标签逐个移除时把退出清单写成空。
- 取消退出：保留冻结的恢复快照；界面不伪报退出成功。已经关闭的标签仍可从冻结快照恢复；下一次明确编辑/开关标签才生成新的活动快照。
- 部分关闭失败：保留恢复点并报告失败，不伪报全部关闭。清单写失败提供重试、取消退出、明确忽略本次清单更新的选择，旧清单不得被半写文件替换。
- 异常终止：仅保证最后成功写出的草稿与清单可以被尝试恢复，不保证尚在内存中的变化或断电零丢失。清单保存与 SQL 保存不是跨文件事务，缺失引用必须是正常可解释状态。

### 隐私与开关

- 独立“记录 SQL 工作区”开关；仅草稿自动保存与工作区记录都开启时记录新清单。关闭不影响当前编辑器，也不自动删除已有恢复点。
- 首用说明：清单本身不存 SQL，但恢复会显示已有本地草稿；现有 SQL 历史仍有独立语义。
- 清空工作区清单只清除布局引用，不删除 SQL 草稿；清空草稿会导致相应布局引用不可恢复，必须更新提示且阻止旧排队任务复活清单。清空错误不报告成功。
- 开关要严格持久化；保存失败仅表示本次不可用，不宣称设置已落盘。保留损坏/未知版本文件，不静默覆盖。未知/损坏清单不妨碍显式 SQL 草稿恢复。

## P2.1 精确数据契约

- `SqlWorkspace(long capturedAt, List<Entry> entries, UUID selectedDraftId)`，嵌套 `Entry(UUID draftId, int anchor, int caret)`；公开不可变值对象。
- `capturedAt >= 0`；条目 0..100 且 UUID 非空、唯一；选中 UUID 空或属于条目；锚点和光标各 0..1048576（P1 最大 SQL 字节数也是合法 UTF-16 长度上界）。拒绝而非静默截断越界输入。
- 二进制大端：magic `0x44435753`，version `1`，long capturedAt，int count，int selectedIndex（-1 或有效索引）；其后每项 UUID 两个 long、int anchor、int caret。头 24 字节，每项 24 字节，最大 2424 字节。
- 编码按列表原顺序；解码在分配条目之前验证长度和 count；拒绝尾随数据、每个截断点、重复 ID、无效选择、负时间/位置及越界。magic 合法但 version 非 1 返回 `UNSUPPORTED_VERSION`，其余不合法返回 `CORRUPT`。格式不是加密或防篡改认证。
- `SqlWorkspaceCodec` 包内；`Failure extends IOException` 带公开到包的 `Code`，固定消息 `Invalid SQL workspace format: <CODE>`、无原始异常 cause。
- `SqlWorkspaceRecovery.resolve(SqlWorkspace, List<SqlDraft>)` 公开纯函数；只消费已经验证的草稿列表（最多 100、无空值、无重复 UUID），不读取文件、查连接或调用 FX。
- `Resolution(List<ResolvedTab> tabs, UUID selectedDraftId, List<UUID> missingDraftIds)` 与 `ResolvedTab(SqlDraft draft, int anchor, int caret)` 是输出。保留完整原文/连接/Schema/时间/UUID及未夹取位置；输入和输出容器不相互共享可变列表。
- 所有公共输入验证使用固定信息，不打印草稿正文/Schema/连接元数据；输出摘要不展开草稿正文。通过真实对象断言而非 mock 调用次数验证。
