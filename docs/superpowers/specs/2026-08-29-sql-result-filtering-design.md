# SQL 查询结果筛选与复制体验设计

## 背景

DataCube 的 SQL 编辑器已经支持独占 JDBC 会话、执行与取消、事务安全、SQL 历史、格式化、补全、执行计划、结果导出和复制 INSERT。当前查询结果直接一次性展示在 `TableView` 中，缺少高频的结果内查找、结构化筛选和通用复制能力；达到读取上限时也没有明确区分“已加载行数”和“数据库总行数”。

本阶段提升日常 SQL 查询后的结果查看效率，同时保持现有会话、事务、取消和关闭语义不变。

## 目标

1. 在查询结果上方提供紧凑工具栏，支持当前结果全文搜索、结构化条件、复制和准确的行列状态。
2. 结构化条件先在当前已加载结果上即时预览，再由用户明确触发数据库筛选。
3. 本地与数据库筛选共用同一套类型化条件模型和从左到右的平面 `AND / OR` 语义。
4. 数据库筛选只处理能够保守证明为可包装、只读、单条 `SELECT` 的 SQL；列名来自结果元数据，值全部使用 JDBC 参数绑定。
5. SQL 错误、超时、取消和关闭竞态不能清空或错误替换当前结果。
6. 明确显示读取上限和截断状态，不把已加载行数描述成数据库总行数。

## 非目标

- 不提供嵌套条件组、任意 SQL `WHERE` 片段输入或完整 SQL AST 编辑器。
- 不自动把全文搜索转换成数据库条件。
- 不支持对多语句、写入语句、`WITH`、集合运算或其他不能保守证明可安全包装的查询执行数据库筛选。
- 不自动执行 `COUNT(*)` 获取数据库总行数。
- 不改变 SQL 编辑器现有事务、只读、生产环境确认、超时、取消和关闭策略。
- 不在本阶段加入结果单元格编辑、聚合、透视或图表功能。

## 用户体验

### 紧凑结果工具栏

结果工具栏位于查询结果表正上方，包含：

- “搜索当前结果”输入框；
- 已添加的条件标签；
- “添加条件”；
- “数据库筛选”或“重新应用”；
- “复制”菜单；
- “清除筛选”；
- 显示行数、加载行数、列数、耗时和截断状态的摘要。

工具栏只在活动结果为查询结果时启用；更新结果、错误视图和执行计划不显示可用的筛选操作。

### 三种结果状态

1. **原始结果**：刚执行用户 SQL 后的不可变结果快照。没有结构化条件时，“数据库筛选”禁用。
2. **本地预览**：全文搜索或结构化条件发生变化后，立即作用于当前已加载结果，不访问数据库。状态文案明确显示“本地预览：显示 X / Y 行”。
3. **数据库已应用**：用户明确点击“数据库筛选”后，使用产生原始结果的 SQL 快照重新查询。成功后原子替换活动结果，并显示“数据库筛选已应用”。再次修改条件后回到“本地预览 / 有未应用更改”。

每次执行新的用户 SQL 都替换原始快照、活动结果和 SQL 快照，并清空旧筛选状态。数据库筛选最多额外保留一个活动结果；原始快照继续保留，以便“返回原结果”不触发网络请求。内存占用因此始终受两个最多 10,000 行的结果快照约束。

“清除筛选”同时清空全文搜索和结构化条件。若尚未执行数据库筛选，它直接恢复原始快照的全部已加载行；若数据库筛选已经成功，它还将活动结果切回缓存的原始快照并清除“数据库已应用”状态，不重新访问数据库。

### 全文搜索

全文搜索只作用于活动结果中已加载、已格式化的单元格文本：

- 忽略大小写；
- 任意列包含搜索词即匹配；
- 输入变化即时更新，允许短防抖以避免大结果集连续重算；
- 不参与数据库 SQL 生成，也不改变结构化条件。

### 结构化条件

一条条件包含：列标识、运算符、类型化值，以及它与前一条条件之间的 `AND` 或 `OR`。第一条条件没有连接符。多条条件严格按界面顺序从左到右计算；数据库渲染器通过逐层括号生成相同顺序，例如 `((A OR B) AND C)`，不依赖数据库默认运算符优先级。

运算符按列类型限制：

- 文本：等于、不等于、包含、开头是、结尾是、为空、非空；
- 数字与日期时间：等于、不等于、大于、大于等于、小于、小于等于、为空、非空；
- 布尔：等于、不等于、为空、非空；
- 无法识别的类型：等于、不等于、为空、非空。

结构化文本比较默认区分大小写；本地使用确定性的 Java 字符串比较，数据库使用参数化的 `=` 或 `LIKE`。数据库自身的字符集和 collation 仍可能影响等价性，界面不宣称跨 provider 的排序规则完全一致。全文搜索与结构化文本条件是两个独立概念，全文搜索仍忽略大小写。

条件编辑器在提交前校验值；无效数字、日期或空必填值保留编辑状态并给出行内错误，不产生本地或数据库执行。

### 复制

结果表启用单元格选择。复制菜单提供：

- 当前单元格；
- 选中区域；
- 选中行；
- 选中行并包含表头。

`Ctrl+C` 复制当前选择的最小矩形区域。多单元格和多行输出为 TSV；包含制表符、换行或双引号的值使用兼容电子表格粘贴的引用规则。复制只读取当前活动结果和当前可见顺序，不访问数据库。

## 架构

### `ResultFilterState`

每个 `SqlEditorPane` 拥有独立的结果筛选状态，包含：

- 原始 `QueryResult` 快照；
- 当前活动 `QueryResult`；
- 产生原始结果的 `lastQuerySql` 快照；
- 全文搜索词；
- 有序 `FilterCondition` 列表；
- 数据库条件是否已应用、是否有未应用更改；
- 数据库筛选资格及不可用原因。

状态不持有 JDBC 资源，也不访问 JavaFX 控件。视图只通过明确方法更新状态并渲染快照。

### 结果列元数据

现有结果模型需要在保留兼容列名访问方式的同时，增加每列的稳定位置、显示标签和 JDBC 类型信息。行数据必须继续保留原始 `Object` 值；字符串格式化只发生在显示和复制边界。这样可以：

- 区分 SQL `NULL` 与空字符串；
- 对数字、日期和布尔值执行类型化比较；
- 为数据库参数选择合适的 JDBC 绑定方式；
- 即使零行结果也能从 `ResultSetMetaData` 获得列类型。

读取结果时最多保留 10,000 行，但需要额外探测是否存在下一行并记录 `truncated`，以显示“10,000+，当前结果已截断”。探测不能把第 10,001 行加入结果。

### `LocalResultFilter`

`LocalResultFilter` 是无 JavaFX 依赖的纯组件。输入原始行、列元数据、全文搜索词和条件列表，输出匹配行的位置或不可变视图。它负责：

- 按显示文本完成全文搜索；
- 按原始类型完成结构化比较；
- 统一 `NULL` 语义；
- 按从左到右的顺序组合 `AND / OR`；
- 不修改原始结果和行顺序。

JavaFX 层可使用其结果更新 `FilteredList` 或替换表格项目，但筛选语义不能写在控件监听器中。

### `SafeSelectEligibility`

数据库筛选资格分析器接收产生当前结果的 SQL 快照，而不是后来可能已修改的编辑区文本。首版采用保守规则：

- 脚本切分后必须恰好一条语句；
- 必须能证明为只读、可作为内联视图使用的顶层 `SELECT`；
- 去除允许的末尾终止符后再包装；
- 拒绝多语句、写入或 DDL、锁定查询、顶层 `WITH`、集合运算，以及 provider 无法证明可嵌套的语法；
- 当前结果列标签必须唯一，数据库筛选涉及的列必须具有可安全引用的标签和受支持类型。

资格失败不影响本地搜索、结构化本地预览和复制。数据库按钮保持禁用，并提供具体原因，例如“结果包含重复列名，请在原 SQL 中为列添加唯一别名”。

### `SafeSelectFilterRenderer`

Oracle 和 PostgreSQL 各自提供小型方言渲染器。渲染器只接收通过资格检查的 SQL、来自结果元数据的列和已校验条件，输出：

- 包装后的 SQL；
- 按占位符顺序排列的类型化参数；
- 用于诊断的非敏感摘要。

逻辑形态为：

```sql
SELECT *
FROM (<original-select>) <generated-alias>
WHERE <parenthesized-predicate>
```

生成别名和列标识符使用 provider 方言的引用规则。用户值不进入 SQL 字符串，统一通过 `PreparedStatement` 绑定。文本 `LIKE` 运算符对 `%`、`_` 和转义字符做显式转义；结构化文本条件默认区分大小写，UI 不承诺跨数据库字符集和 collation 完全一致。

### 数据库执行

数据库筛选扩展现有 `JdbcEditorSession` 的查询执行入口，使其接受“SQL + 有序绑定参数”，但继续复用现有：

- 编辑器独占连接；
- 串行会话操作队列；
- 查询超时；
- `Statement.cancel()`；
- 事务模式；
- 标签关闭和应用退出门禁。

数据库筛选不是新的后台连接，也不能绕过只读或生产环境策略。执行期间禁用重复提交；完成回调必须校验本次操作仍是当前所有者，迟到结果不得覆盖后续执行结果或已关闭标签。

## 错误与恢复

- **资格失败**：禁用数据库筛选，保留本地能力并显示具体原因。
- **重复列名或类型不支持**：数据库筛选保守拒绝，不猜测列身份；本地仍按稳定列位置工作。
- **参数校验失败**：条件编辑器显示行内错误，不提交操作。
- **SQL 错误**：保留原结果、当前条件和选择，显示可恢复错误。
- **超时**：保留原结果，明确显示超时，不改写为普通 SQL 错误。
- **取消**：保留原结果，显示“已取消”，不显示“无结果”或成功。
- **标签关闭或应用退出**：沿用现有关闭协调器取消并等待活动操作；关闭后的回调不得更新 UI。
- **达到读取上限**：显示截断事实；本地筛选文案明确限定为已加载行，不自动执行额外查询。
- **数据库筛选成功**：只有本次受限结果读取成功后才原子替换活动结果；原始快照继续可恢复。

错误消息不得包含凭据、完整连接属性或参数值。必要诊断仅包含 provider、失败阶段和经过清理的数据库错误消息。

## 测试策略

### 纯模型测试

- 各列类型和运算符；
- `NULL` 与空字符串；
- 无效值校验；
- 平面 `AND / OR` 从左到右求值；
- 全文搜索只使用显示文本；
- 原始结果不可变；
- 10,000 行边界和 `truncated` 探测。

### 方言与安全测试

- Oracle/PostgreSQL 包装 SQL 和标识符引用；
- 参数顺序、类型和 `LIKE` 转义；
- 条件括号顺序；
- 单条安全 `SELECT` 通过；
- 多语句、写入、锁定、`WITH`、集合运算和重复列名被拒绝；
- SQL 与诊断摘要不包含用户参数值。

### JavaFX 合约测试

- 原始结果、本地预览、数据库已应用和未应用更改状态；
- 按钮启用条件与具体禁用原因；
- 行数、列数、耗时和截断文案；
- 条件错误不会触发执行；
- 复制单元格、矩形区域、选中行和含表头 TSV；
- SQL 错误、超时和取消后保留当前结果。

### 会话与并发测试

- 参数化查询继续遵守串行队列；
- 取消在 Statement 发布前后都有效；
- 查询超时分类保持正确；
- 新执行、关闭和迟到回调之间不会覆盖错误结果；
- 关闭时 JDBC 资源严格释放，未提交事务策略不变。

### 集成验证

在无外部数据库的默认测试中，用记录型 JDBC 替身验证 SQL、参数和生命周期。Oracle/PostgreSQL 只读 live smoke 继续使用显式授权和完整环境变量门禁；缺少配置时报告真实 skip，不读取应用保存的连接。

## 验收标准

1. 查询结果出现紧凑工具栏，当前结果搜索在 10,000 行边界内保持可交互。
2. 用户可添加多个平面条件并为后续条件选择 `AND` 或 `OR`；本地与数据库渲染遵循相同的从左到右语义。
3. 数据库筛选只在资格检查通过时可用，且所有值均通过 JDBC 参数绑定。
4. 全文搜索永远不会自动访问数据库。
5. 数据库筛选失败、超时或取消时，当前结果不会丢失或被清空。
6. 达到读取上限时显示“10,000+，当前结果已截断”，不显示虚假的精确总数。
7. 复制操作支持单元格、区域、行和含表头 TSV，并遵循当前可见顺序。
8. 所有新增默认测试通过；外部数据库 smoke 在未授权环境中保持跳过。
