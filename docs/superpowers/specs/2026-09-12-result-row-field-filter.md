# 行详情内按字段名筛选

基线 main `f95688e`，独立 `codex/result-row-filter`。延续单条记录纵向核对，解决已有最多 200 个字段列表的定位问题；这是代码与合成场景推导，不是用户研究结论。[DBeaver Data Editor](https://dbeaver.com/docs/dbeaver/Data-Editor/) 的 Record 视图提供记录纵向阅读参照；本轮筛选规则是 DataCube 自身的小范围设计，不声称复制其功能。

## 范围与交互

- 仅行详情窗口增加字段名输入、清空和匹配数，不增加 SQL 主工具栏按钮。原字段列表顺序、同名字段原列号保持不变。提示字在明暗主题、输入框聚焦时均可读，仅对该输入框使用主题提示色。
- 对窗口已有快照的显示列名做字面子串匹配，忽略大小写（Locale.ROOT），忽略输入两端空白；不搜索字段值、类型、隐藏列、超过 200 项的字段或列名被截断的尾部。控制字符与列表显示一致地转为空格，不使用正则。
- 查找词最多 256 UTF-16 单元，超限不截取后悄悄匹配，而是清空候选和正文并给出缩短提示。字段快照仍最多 200 项，列名仍受原 512 限制；不增加数据库或文件 I/O。
- 初次打开沿用原焦点字段。输入只筛选列表，若原选中字段仍匹配则按快照身份保留选择和正文内选区；被排除时清空详情，不自动换成另一字段。清空恢复完整快照列表，但不猜测已失去的选择。
- 输入框内 Enter / 向下键选择首个候选（已有有效选择则保留）并聚焦字段表，随后沿用上下键浏览。Ctrl+F（平台 shortcut）聚焦并全选查找词；Esc 直接关闭，不改为二次退出。清空按钮清空输入并返回输入框。
- 空结果显示“没有匹配的字段”，详情明确无匹配；边界说明始终可见，避免把没搜索的隐藏/超限内容说成不存在。
- 筛选只作用于不可变文本快照；不改变原结果的选择、筛选、列显示、排序、SQL、文件或草稿，不自动复制，不重新查询。后续新结果仍不替换已打开详情。
