# SQL 美化运算符边界

## 问题与范围

固定运算符枚举会漏掉命名参数 `=>`、JSON `#-` / `@?`、距离运算符及扩展符号，甚至把已有运算符的长形式拆成前缀和剩余符号。美化不能靠插入空白改变原有符号边界。

本轮仅改 SqlFormatter，保留引用、绑定变量、数值与编辑器操作路径；不增加解析依赖、连接数据库或执行 SQL。

## 选定规则

- 连续符号按一次扫描保留完整组合，冒号 `::` / `:=` 继续单独识别。
- 运算符中的 `--` / `/*` 开始注释，不能被组合符号吞掉。
- 依 PostgreSQL 词法规则：不包含特殊符号的多字符运算符，其尾部 `+/-` 作为后续一元符号分离；例如 `a*-1`、`a>=-1`。包含 `~!@#%^&|?` 的连续组合整体保留。
- 整个符号段只扫描一次，尾部符号一次输出，避免很长的 `++++` 反复扫描剩余文本。
- 已由空白分开的符号不合并；引用/注释内部仍原样保留。反引号继续沿用项目既有的标识符引用规则，本轮不支持反引号作为 PostgreSQL 自定义运算符字符。
- 统一符号 token 的括号间距判定，不把新识别的运算符当成函数名。

这只是无连接上下文的词法保留，不验证运算符是否存在、操作数类型、运算符名称长度或完整方言语法；不改运算优先级、表达式次序或添加语义括号。

## 依据与验收

依据 [PostgreSQL 运算符词法规则](https://www.postgresql.org/docs/18/sql-syntax-lexical.html#SQL-SYNTAX-OPERATORS)、[命名参数](https://www.postgresql.org/docs/18/sql-syntax-calling-funcs.html#SQL-SYNTAX-CALLING-FUNCS-NAMED)、[JSON 运算符](https://www.postgresql.org/docs/18/functions-json.html)。固定版本文档用于确定词法规则，不代表进行数据库执行验证。

先用完整输出与二次美化断言复现，再实现：覆盖命名参数、组合符号、负号相邻、注释起始、引号/绑定/类型转换、空白分离与长符号段。跑定向测试、完整 clean test 和镜像构建，验收后本地提交并合并回 main，不推送、不发布。
