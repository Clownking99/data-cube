# 查询结果 XLSX 可读性设计

日期：2026-08-30

基线：`77464b2bc53bf71f988d691e4d0d63367e864934`，分支 `codex/safe-result-export`

状态：三项实现及审查收尾完成。已按可见字符规则排除 DEL/C1 的估计宽度，实际输出不变；全量测试 1208 项通过、3 项跳过。上轮合成文件导入/渲染通过，真实 Excel 交互及查询入口直接采样失败注入仍保留验收/覆盖限制。最终证据见 `../verification/2026-08-30-query-xlsx-readability.md`。

## 1. 问题与目标

上一阶段的查询结果导出已经保留中文、空值和纳秒时间内容，但合成数据 XLSX 的渲染预览出现默认列宽遮挡文字。检查实际 OOXML，工作表没有列宽定义，包内没有样式文件。该现象不是已经确认的数据丢失，也不代表已经在 Microsoft Excel 中完成验收。

本轮让查询结果 XLSX 打开后更容易阅读：根据有限样本设置列宽、突出表头、冻结首行、支持长文本换行。只改变展示布局，不改变导出范围、值转换、确认流程或文件发布机制。

## 2. 范围与非目标

- 仅增强 `QueryResultFileWriter` 的 XLSX 分支。
- `XlsxWriter.write(File, List<String>, RowFeed)` 保持原有无样式输出语义；`TableExporter` 的调用及分页流式读取保持不变。
- CSV、SQL、HTML、XML、复制 INSERT、导出对话框和默认文件名均不变。
- 不增加数据库查询、第三方依赖、用户设置、筛选按钮、合并单元格或日期序列值转换。
- 不在本轮解决 Excel 固有的数值精度、单元格长度限制，亦不承诺不同查看器的像素级一致性。
- 已有手工验收中未完成的范围切换、隐藏列及键盘操作检查仍按原记录保留，不因本轮排版改动视为通过。

## 3. 方案比较与决定

1. 固定列宽：实现简单，但无法同时照顾短数值、中文名称与完整时间文本。
2. 表头加前 100 行取样：能覆盖常见查询结果，成本可控，不需要重复消费数据流。采用此方案。
3. 扫描全部行：更容易发现尾部长值，但额外遍历整个结果；超长值仍必须限制列宽，因此不采用。

取样只影响宽度估计；第 101 行及之后的内容仍完整进入原有写入流程。

## 4. 结构与数据流

### 4.1 查询结果布局估计

新增小型、可独立测试的布局估计组件，接收当前导出范围已经投影的列名、原始行视图及取消检查回调，返回不可变的列宽描述。

- 使用 `snapshot.rows(scope)` 对应的顺序与列投影，不访问表格控件、不读取数据库或 JDBC 大字段。
- 当前筛选范围按当前导出顺序取样；全部已加载范围按已加载顺序取样。两者均沿用现有可见列顺序并排除序号列。
- 估计在现有后台导出工作中、特殊值规则校验之后运行，不占用 JavaFX 线程。
- 只保存每列宽度，不复制完整结果矩阵。

### 4.2 显式样式入口

为 `XlsxWriter` 增加接收布局描述的样式入口。旧三参数入口保持原有包结构和写入语义；查询结果显式调用新入口，整表导出不迁移。

样式入口仍只消费一次 `RowFeed`。它在 `sheetData` 之前写入冻结窗格及列宽，并添加必要的样式部件、内容类型声明和工作簿关系。布局列数不匹配等无效配置应在消费数据流前失败，不悄悄采用错误列宽。

### 4.3 保留导出事务边界

流程保持为：原有校验 → 有限布局估计 → 在原有临时文件中写入 XLSX → 原有取消检查与原子发布。

估计失败或取消沿用现有失败路径，不自动降级后发布，也不覆盖已有目标文件。取消检查放在估计开始、每行/每列处理及估计完成处；单个字符串扫描本身有严格上限。

## 5. 列宽规则

宽度是与字体无关的近似字符单位，不使用 AWT、JavaFX 字体测量或查看器的自动列宽功能。

- 每列考虑表头和最多前 100 行；空值贡献宽度 0。
- 最终宽度为 `min(60, max(12, 最大估计内容宽度 + 2))`。
- 字符串最多扫描前 256 个 Unicode 码点；ASCII 可见字符计 1，非 ASCII 可见字符计 2。按码点遍历，不把代理对拆成两个字符。
- 换行以最长已扫描行计宽；CRLF 视为一次换行；制表符计 4；其余 ISO 控制字符（C0、DEL U+007F、C1 U+0080–U+009F）不贡献宽度，但仍占用 256 码点扫描预算。U+007E、U+00A0 仍按普通可见字符计宽。该规则只影响估计，不改变既有 XML 字符输出规则。
- 已达到内容宽度 58 时即可停止扫描，因为最终列宽已经达到上限。
- `String`、`Character`、布尔值、基本数值包装类型、UUID 和现有标准 `java.time` 标量使用其现有文本表示估计。布尔值仍按原有类型写入，不转成字符串。
- 对任意精度数值、URI 和特殊显示值等可能需要昂贵格式化的对象，布局采用固定内容宽度 32，不为测量调用其完整 `toString()` 或大字段读取。正式写入仍使用现有值策略。

扫描边界只约束新增排版工作，不宣称整个文件写入为固定成本。中文和非 ASCII 的双宽处理是保守估计，组合字符等可能略宽；本轮不引入复杂字体度量。

样本之外的长值、超长标题可能仍需用户调整列宽或查看单元格内容；不能为了适配列宽截断实际值。

## 6. 工作表样式与内容契约

- 表头：加粗、浅蓝灰底色 `E8EEF7`、深色文字、允许换行。
- 首行冻结：垂直冻结 1 行，滚动区域从 `A2` 开始；不冻结列。
- 文本单元格：启用自动换行、顶端对齐。数值及布尔值不强制左对齐，保留查看器按类型的默认水平对齐。
- 不强制固定行高，避免主动裁切多行内容；实际自动行高表现需要查看器验收，不能仅凭样式声明承诺长文本始终全部可见。
- 不新增计算公式：以 `=` 开头的文本仍为 `inlineStr`。
- 保留 `Number` 数值单元格、布尔类型、空值省略行为以及原有 XML 转义规则。
- 时间继续作为原有文本写入，保留纳秒，不转成可能损失精度的 Excel 日期序列。
- 不改变特殊值警告或确认要求；已确认导出的是现有显示表示，不把预览值描述成完整大字段内容。
- 工作表名保持 `Sheet1`。仅改变样式元数据和单元格样式引用，不重排、不删减、不重新取数。

## 7. 验收设计

实施时先补充能暴露当前缺少布局行为的回归测试，再实现；本设计提交不新增或执行产品测试。

### 7.1 布局估计

- 覆盖纯表头、空值、中文、完整纳秒时间、换行、制表符及代理对。
- 验证最小/最大宽度、256 码点扫描边界和第 101 行不影响宽度。
- 验证表头参与估计、当前范围与全部已加载范围使用各自顺序、隐藏列不重新出现。
- 验证布局不额外调用任意精度值或特殊值的完整格式化，不触发 JDBC 或数据源读取。
- 取消发生在取样期间时停止后续访问，不能继续写入或发布结果。

### 7.2 OOXML 与兼容性

- 解析实际生成的 ZIP/XML，检查列宽、冻结窗格、表头/正文样式以及内容类型和关系引用闭合；断言行为，不依赖 ZIP 时间戳。
- 核对中文、XML 特殊字符、空值、数值、布尔值、纳秒时间和公式形文本的内容及类型未变。
- 样式入口与旧入口在相同数据上的单元格值和顺序一致。
- 旧三参数入口保持原有部件集合与无样式行为；两种入口均只消费一次 `RowFeed`。
- 回归现有特殊值校验、取消和原子文件保护；新增布局失败/取消不得覆盖已有目标文件。
- 定向测试通过后运行全套测试，记录真实通过、失败与跳过数量。

### 7.3 桌面与文件检查

使用合成查询结果导出，至少含中文姓名、数值、空时间、纳秒时间及一段长文本。检查实际文件并渲染预览，确认短值和时间列更易阅读、表头突出。

冻结及换行优先在可用的真实表格查看器中验证；如只能检查 OOXML 或静态预览，应明确写出未完成的交互验收，不以渲染成功代替真实 Excel 兼容性结论。不得为此访问用户数据库、真实凭证或已有业务文件。
