# 查询结果列显示控制

## 决策与授权

用户已确认新增列显示/隐藏功能，并授权后续常规产品决策由维护代理参考主流数据库工具自主推进，不再逐项询问。本设计与后续实现不扩大到推送、发布、安装器或真实数据库写入。

参考 [DBeaver 的列显示管理](https://dbeaver.com/docs/dbeaver/Data-Filters/#managing-display-of-columns-in-data-table)（2026-08-30 查阅）：逐列勾选与显示全部是可发现、可恢复的交互。DataCube 采用同类概念，不照搬其 SQL 过滤或持久化语义。

比较：JavaFX 内置表角列菜单最省代码，但不能直接满足排除序号列、最后一列保护、明确导出提示；独立列配置对话框适合更多设置，但为一次隐藏增加确认步骤。本次选择结果工具栏“列（可见数/总数）”菜单，立即生效。

## 用户行为

- 仅控制 SQL 查询结果的数据列，序号 `#` 不列入选择器、计数或导出。
- 列菜单按当前显示顺序列出全部数据列，包括已隐藏列。用原始列序号加标签区分同名列；标签中的下划线按原文显示，不作快捷键标记。
- 勾选切换可见性；“显示全部列”恢复隐藏列，不改变列重排、宽度、排序、筛选或结果值。
- 至少一列数据可见，最后一列不能再隐藏；无查询结果时按钮禁用。有表头但零行的查询仍可配置列。
- 同一已加载结果的本地搜索、增删条件、清除本地筛选保留列可见性、顺序、宽度和排序。新查询/数据库重新查询形成的新结果重置为全部列可见，不按同名列套用旧偏好。
- 不把设置写入文件；关闭编辑器后不恢复列偏好。菜单本身不查询数据库、不改变 SQL、不执行复制。
- 两种导出范围和 INSERT 继续使用现有可见列投影，隐藏列不进入输出；筛选条件仍可针对隐藏列，不改变现有搜索语义。

## 实现边界

新增 `SqlResultColumnMenu` 只负责当前 TableView 的列菜单与约束，不知道连接、会话、文件或 SQL。`SqlResultToolbar` 接收可选菜单节点，保持既有构造入口兼容。`SqlEditorPane` 负责当前结果身份与列重建：同一活动 QueryResult 保留列对象；替换结果重新创建列；清空时释放身份引用并禁用菜单。结果行按现有过滤状态重建，再应用现有排序。

菜单打开时从当前表列重建条目；刷新结果时关闭旧菜单，旧条目回调核对列对象仍属于当前结果，避免把旧操作施加到新列。不注册长寿命双向绑定，不保留跨结果列映射。

## 验证与交付

通过实际 MenuItem 动作驱动的 JavaFX 契约测试验证可见性、最后一列、恢复全部、重复标签、零行/无结果、旧回调、新结果重置，以及隐藏+重排+排序+搜索+两范围 CSV 文件内容的组合。夹具使用本地合成数据，无数据库/剪贴板依赖。之后进行独立审查、全套回归和可行的桌面观察。

本增量可在代码、自动化与列控件桌面验证完成后本地合并；未完成的安装升级、真实 Excel 和远端 CI 继续作为发布门槛，而不把发布授权等待变成所有产品增量的合并阻塞。

## 自审

当前结果与新结果生命周期、可见列导出、最后一列、重复标签和非查询状态均有明确行为；不新增持久化、连接或下载依赖。用户已授权自主决策，不再等待第二次设计确认。
