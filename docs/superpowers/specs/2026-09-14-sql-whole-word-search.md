# SQL 整词查找与替换

## 产品决策

当前查找只有字面匹配与大小写开关，`id` 会命中 `user_id`、`id2`，全部替换沿用这些匹配。
本轮在既有 Ctrl+F / Ctrl+H 查找条增加默认关闭的“整词匹配”，减少相似字段名的干扰。
这是代码观察得到的维护者选型，不是用户耗时研究。参考 [DataGrip 的 Words 与大小写选项](https://www.jetbrains.com/help/datagrip/finding-and-replacing-text-in-file.html)，不复制其未验证的内部词法规则。

## 契约

- 开关仅当前 SQL 标签有效，关闭查找再打开保留；新标签默认关闭，不新增持久化或快捷键。
- 仍是字面、非重叠查找；不启用正则、去空格、词干、语义引用重命名或跨标签搜索。
- 开启后，匹配两端必须是文本边界，或相邻完整 Unicode 码点不是标识符连续字符。
  连续字符定义为 `Character.isUnicodeIdentifierPart` 或 `$` / `#`，覆盖字母、数字、下划线、组合标记、补充平面字母等。
  点、逗号、括号、引号和空白可作边界；不在代理对内部断开。
  SQL 注释、字符串和引号内名称仍属于普通文本，并不会因“整词”被排除。
- 查询可包含空格/标点；检查整个字面片段外侧的边界。拒绝的候选不能吞掉与之重叠的后续有效候选。
- 默认及原三参数 `SqlTextSearch.find` 行为不变；其他只读正文查找不自动开启整词模式。
- 计数、前后循环、当前替换和全部替换使用同一组结果。切换选项只重新计算，不编辑文本、不移动选区；
  旧查找和替换任务取消且迟到回调失效，等待时禁止替换旧结果。
- 保留 1,024 UTF-16 查询限额、10,000 个有效匹配限额、取消机制、单步撤销、关闭/忙碌/焦点守卫。
  计数上限仅计算通过边界检查的匹配。替换不自动保存源文件或执行 SQL。
