# DataCube：连接到开始查询的体验设计

日期：2026-08-28

状态：产品范围与书面设计均已获用户确认；任务 1 验收完成；任务 2 已实现，最后布局调整后的非跳过回归与桌面复验待完成；任务 3 尚未实施。见 `docs/superpowers/verification/2026-08-28-workspace-start.md` 与 `docs/superpowers/verification/2026-08-28-connection-test.md`。

## 1. 目标与依据

让用户打开 DataCube 后知道下一步如何开始，在测试连接时能看到反馈，在没有可用 SQL 连接时知道如何继续。

本轮在提交 `81c3f2e` 上启动当前代码，观察了启动、新建连接、未选择连接的新建 SQL 三个界面。发现：

- 启动后的右侧工作区没有说明或行动入口。
- 新建连接包含环境、只读和查询超时配置；测试操作在 FX 事件处理器中同步等待网络返回。
- SQL 页已有“未绑定连接”状态，但缺少选择连接的指引，执行按钮仍然突出显示。
- 新建连接表单的可访问性树未报告清晰的输入框名称，需要补齐标签关联并验证。

本地观察记录在 `build/product-audit/2026-08-28/audit.md`，截图为同目录的 `01-start.png`、`02-connection-dialog.png`、`03-unbound-sql.png`。该目录为忽略的临时审视产物，不作为克隆仓库后运行或验收的依赖。观察没有使用真实凭据测试连接、执行 SQL，也不代表用户访谈或完整无障碍评估。

## 2. 范围与取舍

采用一个有限增量，同时覆盖空工作区、连接测试和未绑定 SQL 提示。

其他方向：只添加开始页改动最少，但无法处理连接等待；全面重做工作台与查询管理范围较大，当前证据不足以支持。用户已认可有限增量方向。

本阶段不添加数据库类型、AI、连接分组、最近连接列表、会话恢复、遥测或新的查询管理功能。不修改数据库协议、连接配置文件格式、凭据加密方案、事务语义和发布版本。不自动推送或打标签。

## 3. 产品行为

### 3.1 空工作区：提供下一步，不占用常驻标签

- 只在没有内容标签时显示轻量开始提示，关闭最后一个标签后重新出现；已有标签时完全隐藏，不覆盖正在工作的页面。
- 标题“开始使用 DataCube”，正文“新建连接，或在左侧选择已保存的连接后开始工作”。
- 主操作“新建连接”复用现有连接对话框；次操作“选择已有连接”仅聚焦左侧连接树，不自动选中、展开或连接任何节点。
- 补充关系型连接的路径说明：“选择 PostgreSQL / Oracle 连接后，点击顶部‘新建 SQL’。”Redis 保留现有控制台与键浏览路径，不引导至 SQL 执行。
- 不读取第二份连接存储，不展示凭据、连接地址或查询内容；不新增持久化状态。
- 复用当前字体、主题、按钮与间距习惯，不增加卡片仪表盘、插画或新的导航层级。

### 3.2 测试连接：明确状态，保留独立保存

新建和编辑连接共用同一行为，继续支持 PostgreSQL、Oracle 和 Redis。

| 状态 | 展示与可操作行为 |
| --- | --- |
| 未测试 / 表单已修改 | 显示“尚未测试当前配置”；允许编辑、测试、保存、取消 |
| 校验不通过 | 不发起后台请求，保留表单；使用现有校验规则提示问题并聚焦相关输入 |
| 测试中 | 显示进度及“正在测试连接…”；禁用表单、测试和保存，保留关闭与取消 |
| 成功 | 显示“连接成功，可保存配置”；恢复编辑、测试和保存，不自动保存或关闭 |
| 失败 | 显示安全的失败说明和检查项；恢复编辑、重试和保存，不清空输入 |
| 提交任务失败 | 显示“无法开始连接测试，请稍后重试”；退出忙碌状态，表单仍可用 |
| 已关闭 | 不再更新界面、不弹出结果、不写入连接存储 |

- 测试按点击时的表单快照执行，后台不能读取 JavaFX 控件。编辑连接时“密码留空沿用原密码”的语义不变。
- 任何字段修改后，之前的成功或失败状态立即失效，回到“尚未测试当前配置”，避免把旧结果当成新配置验证结果。
- “保存”仍只保存有效配置，不隐式测试或连接，也不要求测试成功。测试中暂时禁用保存，防止对同一个对话框的生命周期作并发操作。
- 一个对话框内最多一个测试请求在途，快速连点不能创建多个请求。
- 网络失败提示至少提供“检查主机和端口、数据库或服务名、凭据及网络后重试”的可操作说明，不未经证据把所有错误归类为密码错误。
- 本阶段不直接展示或复制原始异常、完整连接 URL 或配置对象；不能把密码、密文或临时明文属性写入新日志或提示。可以使用不含敏感数据的通用错误文案。
- 取消按钮和窗口关闭均关闭对话框，不保存；请求中断后台测试，并抑制已排队的迟到回调。它不是独立的“取消测试但保留窗口”功能。
- 不把“查询超时”描述为连接测试超时；本阶段不引入跨驱动统一硬超时。驱动可能不立即响应线程中断，界面关闭不等于底层请求已立即停止；其实际结束后必须走现有临时连接资源清理路径。
- 表单标签关联对应输入框，类型变化时更新数据库/服务名等名称；用文字表示状态，不仅依赖颜色。验证键盘焦点、Tab 顺序和读屏名称。

### 3.3 未绑定 SQL：区分候选连接与固定连接

- 没有关系型候选连接且没有固定连接时，显示“请先在左侧选择 PostgreSQL 或 Oracle 连接，再执行 SQL”。
- 当前候选为 Redis 时，明确说明 Redis 不支持 SQL，应使用其控制台；不能把它标成可执行 SQL 的候选连接。
- 在没有可用关系型连接时禁用执行和执行计划；F5 等快捷入口仍保留连接校验，不通过另一条入口发起网络工作。编辑与美化 SQL 不受影响。
- 选中关系型候选后显示“待绑定：连接名称”，提示首次执行或会话操作将固定连接；不能将未建连状态文案写为“已连接”。
- 环境和只读状态只在有对应关系型连接时显示；没有连接时不使用“开发”标签暗示存在可用开发库。
- 已固定连接的编辑页始终显示固定连接；选择左侧另一连接不能改变该页绑定、事务或执行目标。
- 新增可用性判断必须与既有执行中、关闭中和事务操作状态共同生效，不能因为选中了连接就重新启用本应禁用的按钮。
- 提示展示本身不触发建连或元数据读取；现有显式选择连接引起的元数据预热行为不在本阶段重构。

## 4. 组件与数据流

### 空工作区

由 `AppShell` 组合轻量开始提示与现有 `ContentTabPane`。提示组件只接收“新建连接”“聚焦连接树”两个回调，不依赖 JDBC、配置存储或密码处理。

`ContentTabPane` 提供只读的空标签状态，仍由原受管标签机制负责增加、移除和关闭。开始提示不插入伪标签、不改变原 `getNode()` 的返回含义、不修改关闭守卫。空状态切换不能移除或清理实际内容组件。

### 连接对话框

`AppShell` 已拥有应用级 `FxTaskRunner`，`ConnectionTreePane` 负责将它传入新建和编辑对话框入口。每次对话框建立独立 `FxTaskScope`，不创建自己的全局执行器。

数据流为：FX 线程校验并取得不可变配置快照 → 设置测试中 → scope 提交 `ConnectionManager.test(snapshot)` → FX 回调更新成功或失败状态。

对话框隐藏时关闭自己的 scope，不关闭应用 runner。构建或显示失败也必须释放已创建的 scope。任务提交被拒绝时同步恢复界面状态。`ConnectionManager.test` 正常返回 `null` 才表示连接成功，返回错误字符串表示测试失败；不能把任务正常完成等同于连接成功。异常回调同样进入失败状态，所有完成路径都恢复可操作状态。

使用小型连接测试状态组件封装忙碌、结果失效和关闭状态，便于注入可控测试操作。控制器不负责连接存储、凭据解密或真实协议实现。

继续复用 `ConnectionManager.test` 和各 provider 的测试流程；不得调用缓存连接获取路径来代替测试，不把测试连接发布为 SQL 会话。

### SQL 引导

复用 `SessionContext` 的活动连接通知及 `SqlEditorConnectionAdmission` 的固定连接规则。`SqlEditorPane` 根据已有状态更新提示和按钮，不引入第二套连接绑定来源。已有的监听清理、执行准入、事务和严格关闭流程保持不变。

## 5. 验收与验证

| 验收项 | 验证方式 |
| --- | --- |
| 空工作区展示引导，打开任意内容标签后隐藏，关闭最后一页后恢复 | UI 状态测试和人工观察；受管标签关闭被拒绝时保持原内容 |
| “新建连接”行为与顶部入口一致；“选择已有连接”只聚焦树 | 回调测试及 UI 检查；断言没有额外存储读取、自动选择、展开或网络请求 |
| 无连接和仅有 Redis 时，SQL 提示清晰且不能执行 | 状态测试覆盖按钮与快捷键入口；不触发 provider 调用 |
| 候选 A 进入执行准入后固定为 A，切换左树 B 不改变目标 | 运行现有连接准入、专用会话和事务相关回归测试 |
| 慢测试不阻塞 FX 线程，重复点击只发出一次测试 | 可控阻塞桩与 FX 心跳验证，不依赖公网或真实数据库 |
| 成功、失败、任务拒绝都能退出忙碌；失败保留输入 | 可注入操作桩与对话框契约测试，覆盖新建/编辑和三种类型 |
| 改字段使之前结果失效；保存不隐式测试 | 状态测试与服务调用计数；编辑密码留空沿用原密文 |
| 测试中关闭后，迟到成功和迟到失败都不再触达 UI | 可控完成顺序的生命周期测试，包含回调已排队的情形 |
| 测试临时资源在操作结束时清理，不创建缓存会话 | 服务与 provider 边界测试，取消不等价于确认驱动已停止 |
| 结果文字与日志不泄露凭据；输入框有可访问名称 | 敏感值哨兵测试、可访问性树及键盘检查 |
| 原有功能不退化 | Windows 全量测试；有显示环境时运行 UI 测试，Linux 无显示环境按既有规则跳过并明确报告 |

测试先覆盖关键状态与生命周期，再实现改动。人工验收使用测试配置和模拟失败，不使用工作区已保存的公司数据库凭据。

最终验证包括 `gradlew.bat clean test --no-daemon --console=plain`、当前版本 UI 截图及 `git diff --check`；记录真实结果，区分通过、跳过和未验证。本文阶段只做文档检查，不将此前测试结果视为此次验证。

## 6. 实施边界与风险

- 不重做连接树展开和刷新流程；回归覆盖之前修复的展开显示问题。
- 保留深浅主题与当前工具栏，开始提示不扩展为独立主页系统。
- 暂不承诺真实网络响应时间、驱动立即取消或完整无障碍合规。
- 不使用遥测或下载数据证明效果；本阶段成功标准是上述可重复的操作和测试结果。
- 保留工作区现有未跟踪 `.testagent/`，不读取、修改或暂存它。
- 设计确认后再编写实施计划；本设计文档提交不代表功能已交付。

## 7. 设计自审

- 范围对应已认可的三项改进，无新数据库能力或外部服务。
- 保存、测试、选中候选、固定连接及真实建连已明确区分。
- 网络测试快照、单请求、失败恢复、关闭和迟到回调有明确归属。
- 没有把 UI 可取消误写为驱动立即终止，也没有修改既有查询超时语义。
- 每项用户行为对应验收，未留下待选方案或未定义占位内容。
